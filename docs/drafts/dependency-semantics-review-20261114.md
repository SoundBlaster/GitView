# Семантика зависимостей GitView

Срез 78 candidate nodes от 14 ноября, после проверки 0078. Это авторский
review, а не решение об утверждении graph topology и не исчерпывающая проверка
всех рёбер. Исходные смыслы из локального checkout SpecGraph
[`SG-SPEC-0001`, `edge_kinds`](../../../0AL/SpecGraph/specs/nodes/SG-SPEC-0001.yaml):
`depends_on` описывает невозможность завершить **или проверить** source без
target; `refines` описывает уточнение или декомпозицию target. Различие имеет
значение даже если визуальный обход показывает обе стрелки.

Ранее [аудит 0078](issue-links-readiness-20261114.md) указал 36 достижимых
узлов **включая сам 0078** по объединению `refines` и `depends_on`. Это не
36 обязательных блокеров и не транзитивный `depends_on` closure. Кроме того,
снимок сделан до удаления одного ребра. Для текущих байтов результаты отдельно
записаны в [evidence](evidence/autonomous-goal-dependency-reachability-20261114.json):

| Узел | Достижимые узлы по `depends_on` | По объединению двух видов рёбер | Прочтение |
| --- | ---: | ---: | --- |
| 0078 — Issue links | 22 | 28 | Включены транзитивные узлы; каждая отдельная необходимость ещё не доказана. |
| 0077 — Issue discussion | 19 | 26 | Нужно отдельно проверить, какие общие зависимости применимы именно к метрикам обсуждения. |
| 0075 — grid gestures | 43 | 50 | Подозрительно широкий контекст для жестов; проверить нижележащие рёбра, а не механически удалять прямые. |
| 0040 — testability | 9 | 14 | Общая инженерная обязанность; отсутствие ребра к ней не отменяет требований родителя 0021. |
| 0043 — cross-branch scenarios | 63 | 70 | Широкий охват ожидаем для сквозных сценариев, но набор прямых связей следует сверить с конкретными сценариями. |

Числа выше исключают сам исходный узел; повторно достижимые узлы считаются
один раз. Подсчёт не определяет критический путь, реализационный порядок,
одобрение или количество нерешённых вопросов.

## Решение для 0078

Удалено прямое `depends_on: 0063`: 0063 определяет производный Project signal
«открытая Issue с открытым blocker», тогда как 0078 описывает source links,
их направления, доступность и прямую иерархию независимо от наличия такого
сигнала. Само обсуждение blocker в 0078 не делает весь сигнальный контракт
предпосылкой проверки общего контракта связей. 0063 остаётся самостоятельным
кандидатом и не меняется. Это корректировка candidate topology, а не изменение
онтологического actor/action отношения.

Прямые зависимости 0024 и 0033 оставлены: 0078 отдельно использует возврат в
исходный контекст и оригинальную ссылку, хотя 0033 уже зависит от 0024. Аналогично
оставлены 0036, 0038, 0044 и 0053: privacy, identity, coverage и conflict
непосредственно участвуют в acceptance и сценариях 0078. Транзитивная
достижимость сама по себе не показывает, что прямая семантическая зависимость
лишняя; удаление только ради уменьшения числа рёбер скроет основания контракта.

Оставшийся широкий closure может включать исторически избыточные рёбра в
предках; настоящий проход не пересматривал их все. Независимо реализуемым листом
0078 не признан: source mapping, access и подтверждение выбранного UI ещё открыты.

## Следующий шаг

Пройти источник широкого closure у 0075 и его непосредственных родителей,
сопоставив каждый спорный `depends_on` с обязательством, без которого действительно
нельзя завершить или проверить узел. Отдельно проверить применимость
cross-cutting testability: наличие родительского принципа и его фактическая
проверка для каждого листа — разные вещи.
