# Отметки review на карточке PR

По последующему решению пользователя (`excerpt-52`) визуальная проверка отметок
пока отложена. Приоритет — полнота онтологии и затем граф спецификаций на ней.
Настоящий документ остаётся предложением; новая редакция макета не создаётся.

Статус: пользователь предложил рабочую кодировку «наверное»
(`conversation:gitview/excerpt-50`): глаз для review, галочка для готового review
без открытых тредов и предупреждение для вопросов. Конкретные условия ниже —
уточнение агента, ещё не согласованное пользователем. Это не canonical spec
и не объявление новых ontology entities.

## Предлагаемый смысл

| Отметка | Условие — предложение агента |
| --- | --- |
| 👁️ | PR ожидает review; это не утверждение, что кто-то сейчас читает код. |
| ✅ | Итог review — одобрено, открытых тредов нет; оба факта известны и актуальны. |
| ⚠️ | Запрошены изменения или есть открытые review threads. |

Завершённое review может содержать запрос изменений, поэтому одного факта
завершения недостаточно для ✅. Предлагаемый приоритет при нескольких сигналах:
⚠️ → 👁️ → ✅. Точные источники и правила оценки review предстоит связать с
согласованным ориентиром на GitHub. Неизвестные или неполные данные не становятся
✅; в preview нужен явный текст «Состояние review неизвестно».

Предложение дополнительного различия: известное отсутствие требования review
можно показывать без отметки, неизвестное состояние — отдельным нейтральным `?`.
Это ещё не выбранный четвёртый значок. Для Issue эти PR-review отметки не
применяем автоматически к комментариям.

## Сочетание с маленькой клеткой

Цвет клетки отвечает за CI, значок PR/Issue — за тип, отдельная небольшая
отметка — за review. Кандидат расположения: тип сверху слева, review сверху
справа, номер снизу. Например, зелёная клетка с ⚠️ означает успешный CI и
вопросы review; красная с ✅ — одобренное review без открытых тредов при
проблемном CI. ✅ не означает общую готовность к merge.

Текст preview объясняет предупреждение: например «Запрошены изменения» или
«3 незакрытых треда». Совмещение отметок и читаемость при 8–10 колонках надо
проверить визуально; текущие HTML-прототипы этим обсуждением не изменены.

## Нативные кандидаты

Для iOS предлагаем SF Symbols вместо цветных emoji: `eye`, `checkmark.circle`,
`exclamationmark.triangle`. Имена проверены через установленный Apple
`sfsymbols search --match-style exactName --json`: все три присутствуют;
каталог сообщает monochrome availability с iOS 13.0. Deployment target GitView
ещё не выбран, runtime-код не добавлен; проверка каталога не доказывает
читаемость символов в маленькой клетке. Rendering mode согласуем отдельно.

масштабе и сохранить новую редакцию HTML/CSS/JS-прототипа.
