# Project: согласованные состав, сводка и погружение

Статус: пользователь согласовал предложение о свойствах Project, сводке и
двух путях погружения (`conversation:gitview/excerpt-41`: «Ок, меня устраивает.»).
Выбраны блоки A–C с условиями применимости ниже. Точные правила вычислений,
обновления и переходов остаются предметом спецификаций. Это не изменение
ontology package, утверждение всего sketch или создание canonical specs.
Исходное предложение агента (`excerpt-40`) и ответ сохранены отдельно в SpecDraft.

## Согласованная основа

Project содержит один или несколько репозиториев; один репозиторий может входить
в разные проекты. По умолчанию один Project соответствует одному репозиторию.
Репозитории могут принадлежать разным GitHub organizations; organizations —
метаданные, не обязательные границы Project. Отдельная сущность Group не нужна.
Речь о Project GitView, не об отдельной возможности GitHub Projects.

## A. Собственные свойства Project

- [x] A1. Устойчивый локальный ID.
- [x] A2. Название.
- [x] A3. Необязательное описание назначения проекта.
- [x] A4. Состав: ссылки на GitHubRepository.

Состав хранится через идентичность репозиториев; Project не копирует их данные
и не меняет владельца репозитория. Название проекта может отличаться от имени
репозитория. Имена, ссылки и состав отделены от смыслового определения Project.
Форматы Problem/Motivation для Issue/PR не распространяются на Project молча.

## B. Сводка по составу

Используем те же понятные показатели, что в [сводке Repository](repository-summary-proposal.md),
с областью подсчёта «все репозитории этого Project»:

- [x] B1. Число репозиториев и полнота охвата: например, данные доступны для 4 из 5.
- [x] B2. Открытые PR, из них draft; открытые Issue — раздельно.
- [x] B3. Сигналы внимания: PR с красным CI, ожиданием review, запрошенными
  изменениями; незакрытые треды и PR с ними; Issue с открытыми blockers.
- [x] B4. Предварительная выборка «проверки и review пройдены», если правило
  Repository D будет выбрано. Это не гарантия merge.
- [x] B5. Merged PR и закрытые Issue по причинам за один выбранный период.
- [x] B6. Графики тех же показателей при наличии достаточной истории.

Для сигналов полезны два масштаба: «3 PR с красным CI в 2 репозиториях».
Это число объектов и число затронутых репозиториев; их не складываем.

Членство репозитория в другом Project не исключает его из текущей сводки.
В общем итоге портфеля нескольких Projects каждый репозиторий и его объекты
учитываются один раз. Итоги проектов нельзя просто складывать: их составы
пересекаются. Числа PR и Issue тоже не складываются в число независимых задач.

Период и фильтры одинаковы для сравниваемых частей сводки. Недоступность одного
репозитория делает итог неполным; не означает ноль объектов в этом репозитории.
Актуальность CI, PR и Issue сохраняется при агрегации, а не заменяется одним
оптимистичным временем обновления Project.

## C. Два способа погружения

- [x] C1. При приближении Project раскрывается в сетку репозиториев, затем —
  в их PR и Issue. Объект сохраняет контекст исходного репозитория.
- [x] C2. Выбор счётчика Project сразу открывает общую отфильтрованную выборку
  объектов всех его репозиториев, например все PR с красным CI. У каждой строки
  или карточки виден репозиторий; предварительный обход репозиториев не нужен.

Это два пути к одним данным: через состав или через интересующий сигнал.
На дальнем масштабе Project показывает название, число репозиториев и несколько
счётчиков. При приближении раскрываются детали. Система цветов и компоненты
следуют выбранному Apple Look; отдельный цвет «здоровья» всего Project пока
не предлагается.

Для Project из одного репозитория сохраняем тот же смысл сводки,
но не заставляем проходить две одинаковые карточки. Сразу раскрываем
его PR и Issue; Project и Repository при этом не становятся одной сущностью.
Точная механика перехода, возврата и pinch — будущая UX-спецификация.
Календарный масштаб остаётся отдельным представлением времени, не новым
уровнем членства Project.

## Иллюстративный пример

```text
Apple Apps
3 репозитория

19 открытых PR · из них 3 draft
23 открытых Issue
3 PR с красным CI в 2 репозиториях

Репозитории: Dreams · SessionMonitor · GitView
```

Числа и объединение в примере вымышлены, не считаны из GitHub и не создают
реальный Project пользователя. Выбор сигнала «3 PR с красным CI» должен вести
к этим трём PR из двух репозиториев по той же области подсчёта.
