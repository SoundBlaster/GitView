# GitView: первичная сортировка структурных листьев

Срез на 14 ноября содержит **121 candidate и 54 структурных листа**, все
`idea / pre_canonical`. Каждый узел достигает корня по `refines`; объявленные
ссылки существуют, циклов в проверенных множествах рёбер нет. [Инвентарь с SHA,
рёбрами и исходными unresolved](evidence/autonomous-goal-graph-readiness-121-triage-20261114.json)
фиксирует проверенные версии.

Это полная структурная сортировка листьев по одной основной области, **не
поузловой semantic audit**: области пересекаются, а содержание каждого узла и
его транзитивных условий ещё нужно оценить отдельно. Ни число сценариев, ни
отсутствие структурных ошибок не доказывает completeness, acceptance или
implementation readiness. Старые группировки сверены с новым срезом: каждый
текущий лист отнесён ровно к одной основной области.

## Общие препятствия, требующие проработки

- **Source-to-domain:** установить доступность и смысл данных для identity,
  Today, CI/review, Issue dependencies и истории. Для неподтверждённой полноты
  нужен полезный и честный ограниченный результат.
- **Хранение и доступ:** связать выбор provider, границы транзакций,
  checkpoint, Keychain и восстановление с продуктовыми инвариантами. Ошибки
  реального устройства проверяются позже; отсутствующее решение о границе
  нельзя заменить описанным сценарием.
- **Составные маршруты:** завершить входы и выходы source, storage, decision и
  navigation для setup и Project → Today; сверить их с FSD и SpecificationCore.
  Допущения агента остаются помечены как таковые.
- **Cross-cutting:** отдельно проверить доступность, приватность, DI/TDD и
  предотвращение потери данных по применимым маршрутам. Наличие ребра
  зависимости не доказывает применимость и согласованность требования.

Два устаревших unresolved уточнены: 0023 теперь ссылается на кандидатные
правила access ordering, а 0078 различает ограниченное evidence отдельного
dependency event и неподтверждённую полную историю. Это не объявляет ни одно
из решений принятым или проверенным в приложении.

Следующий проход — разобрать source-to-domain для Today и durable observation
boundary по документированным возможностям источника; затем оценить каждый
затронутый лист по входам, результатам, ошибкам и транзитивным зависимостям.
До завершения продуктового графа приложение и интеграционный пилот не
реализуются.
