## Как использовать сверку

1. При изменении source intent уточнить соответствующие узлы и обратные ссылки.
2. Проверять итоговый branch вместе с предками, `depends_on` и сценариями на
   границе соседних branches; одно наличие ссылки в таблице не является gate.
3. Новые решения агента маркировать как предложения и не переносить кнопки или
   визуальные состояния в ontology без отдельного предметного основания.
4. По мере работы обновлять пробелы; source-specific исследования не подменять
   предположениями или заранее выбранными числовыми API limits.
