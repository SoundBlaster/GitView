# Today: операции, поля, права и границы свидетельств

Рабочая матрица для первого направления [0102](GITVIEW-SPEC-0102.yaml), нормализации [0101](GITVIEW-SPEC-0101.yaml) и обмена [0116](GITVIEW-SPEC-0116.yaml). Today объединяет открытую работу, создание и подтверждённые закрытия или merge в локальном дне; одна карточка может подходить по нескольким основаниям. Это не законченный набор query, не проверка реального аккаунта и не полный перечень полей карточек PR/Issue.

## Рабочий профиль для выбранных операций

0102 выбирает четыре перечисленные GraphQL-операции и typed timeline при необходимости как начальный путь Today. В 0100 для регистрации предложен рабочий read-only профиль: Metadata, Issues и Pull requests для базовой области; Checks и Commit statuses — для отдельно выбранных CI-счётчиков. Это привязка к продуктовым категориям и REST-аналогам, а не доказанная карта permissions GraphQL, минимальности профиля или доступа установки. Для недостаточных прав, ошибки страницы или поля используются независимые observations и scoped limitation; точная причина указывается только при достаточном свидетельстве. Документация GitHub прямо предписывает проверять GraphQL permissions для запросов приложения в [Choosing permissions](https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/choosing-permissions-for-a-github-app).

## Permission и validation boundary

GitHub указывает, что permissions для GraphQL requests не документированы в такой же карте, как REST, и конкретные запросы приложения следует проверять: [миграция OAuth Apps к GitHub Apps](https://docs.github.com/en/apps/creating-github-apps/about-creating-github-apps/migrating-oauth-apps-to-github-apps), [выбор permissions](https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/choosing-permissions-for-a-github-app). Поэтому `Metadata`, `Issues` и `Pull requests` в текущем profile — кандидаты на основании других документированных операций, а не подтверждённый минимальный набор для этих GraphQL fields. Реальной авторизованной проверки не проводилось.

Ошибка GraphQL request validation предшествует пригодным данным; execution errors могут сосуществовать с частичным `data`, а non-null propagation затронуть родительский объект или список. Разбирать ошибки нужно по фактической форме и alias пути, не подставляя null или omission как empty: [GraphQL response](https://spec.graphql.org/September2025/#sec-Response), [execution errors](https://spec.graphql.org/September2025/#sec-Handling-Execution-Errors). Ни одна строка таблицы не утверждает полный Today, history или согласованный snapshot.

Проверена опубликованная документация, не live source. Документы кандидатов Today и closure прошли только статическую проверку по сохранённому public schema snapshot. Identity association между API, доступ конкретного user-token, runtime semantics и пути восстановления остаются открытыми. Размеры страниц и API budget здесь не выбираются.
