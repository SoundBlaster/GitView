## Порядок разрешения зависимостей

1. Проверить предложенную source-модель 0101 и перечень требуемых фактов для
   0027, опираясь на документацию GitHub. Выбор source operations должен
   определять значения и границы доказательств, но не преждевременный page size
   или численный API budget.
2. На этой основе конкретизировать 0102 и 0116: в каких условиях известны
   предметные факты, coverage, точные counts и materialized cards, и какой
   результат доступен без доказательства полноты.
3. Для 0105 завершить границы durable effect и восстановления, затем передать
   их в 0116. Не считать успешный запрос автоматически сохранённым.
4. Завершить типизированную policy 0110 и собрать 0115 из устойчивых входов.
   Логическое правило может быть предметно ясным раньше интеграции, но его
   индивидуальная готовность не закрывает готовность всего маршрута.
5. Пересмотреть предков, соседние ветви и cross-cutting requirements; провести
   независимую содержательную оценку, прежде чем объявлять граф достаточным.
