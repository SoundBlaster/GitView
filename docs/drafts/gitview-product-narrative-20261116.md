# GitView: как пользователь видит работу

Это чтение продуктовой идеи по спецификациям на локальной ревизии `f07d3ac`. Оно предназначено для обсуждения: приложение ещё не подтверждено работающей реализацией, а открытые детали в конце не выбраны автоматически.

## Зачем приложение

GitView — личный обзор работы в GitHub, в том числе большого потока PR и Issue от coding agents. Он помогает увидеть, что ещё выполняется, что уже завершилось и куда стоит обратить внимание. Из обзора можно перейти к оригиналу на GitHub. [Общее намерение](../../specs/nodes/GITVIEW-SPEC-0001.yaml)

## Начало работы и Projects

Пользователь подключает GitHub и выбирает доступные репозитории. При обычном подходе одному репозиторию соответствует один GitView Project, но Project может объединять несколько репозиториев, включая репозитории из разных организаций. Один и тот же репозиторий может входить в несколько Projects. Project GitView не тождественен GitHub organization.

Обзор помогает увидеть Projects и их работу. При обычном открытии Project с несколькими репозиториями пользователь попадает в общую сетку PR и Issue; список репозиториев находится в настройках Project. Для Project с одним репозиторием не нужен лишний промежуточный экран. Точный первый экран после запуска и детали настройки остаются открытыми. [Подключение](../../specs/nodes/GITVIEW-SPEC-0019.yaml) · [Первый запуск](../../specs/nodes/GITVIEW-SPEC-0022.yaml) · [Обзор](../../specs/nodes/GITVIEW-SPEC-0004.yaml) · [Project](../../specs/nodes/GITVIEW-SPEC-0006.yaml)

## Today: работа не исчезает при завершении

Today показывает в выбранном Project незавершённую работу, даже если она началась раньше, и работу, завершённую сегодня по местному времени пользователя. Вчерашнее завершение само по себе уже не включает объект в следующий день; другие применимые условия могут включить его.

Без применимого сохранённого исключения вместе видны подходящие PR и Issue в разных состояниях, включая merged и closed. У каждого объекта одна ячейка: когда PR вливается, меняется его состояние, но в этот день его ячейка не исчезает из нефильтрованного Today. Связанные PR и Issue — разные объекты, каждый со своей ячейкой.

Фильтрами можно скрыть, например, merged или closed. Выбранные фильтры сохраняются между запусками и восстанавливаются там, где применимы. Пустой результат и неполученные данные различаются: отсутствие сохранённого исключения ещё не доказывает, что GitView получил все объекты GitHub. [Today и фильтры](../../specs/nodes/GITVIEW-SPEC-0007.yaml)

## Приблизиться и заглянуть

Сетка вдохновлена Photos. На плотном масштабе можно окинуть взглядом много небольших ячеек и различить PR, Issue и важные состояния. Пример масштаба — около восьми ячеек в ряду и ста объектов; это ориентир для дизайна, а не гарантированное число для любого устройства.

Pinch дискретно меняет детализацию. При достижении предельного размера ячейки происходит переход к следующему уровню для определённой цели; граница зависит от ширины сетки и выбранного максимального размера в points. Пока цель неоднозначна, приложение не должно подставлять другой объект. Точный способ выбора цели и обратного перехода предстоит уточнить.

В первой версии долгое нажатие открывает статичный preview выбранного Project, Repository, PR или Issue: можно посмотреть доступные подробности, закрыть preview либо открыть тот же объект. При возврате сохраняется доступный исходный контекст: область, период, фильтры и масштаб; позиция восстанавливается по возможности. Альтернатива долгому нажатию также должна давать доступ к preview. [Сетка](../../specs/nodes/GITVIEW-SPEC-0014.yaml) · [Preview](../../specs/nodes/GITVIEW-SPEC-0015.yaml)

## Понять состояние и найти источник

Карточка PR показывает доступные название, номер, описание и ссылку на GitHub, состояние, контекст репозитория и выбранные счётчики: изменения строк, файлы, коммиты, CI и review threads. Для CI предусмотрены отдельные счётчики красных, жёлтых, зелёных и общего числа проверок. Состояние CI, review и незакрытых тредов остаются разными фактами: отсутствие данных не становится зелёным статусом или нулём.

Карточка Issue показывает доступные название, номер, описание, состояние и контекст, а также выбранные связи и счётчики. Закрытый Issue не обязательно означает завершённую задачу. Связь Issue с PR сама по себе не доказывает мотив автора. Содержимое отдельных review threads и комментариев просматривать внутри GitView не требуется: к источнику можно перейти на GitHub. [PR](../../specs/nodes/GITVIEW-SPEC-0008.yaml) · [Issue](../../specs/nodes/GITVIEW-SPEC-0009.yaml) · [Review](../../specs/nodes/GITVIEW-SPEC-0062.yaml)

## Внимание, готовое и динамика

Сводка Project помогает найти текущую работу и сигналы внимания: например, красный CI, review, запрос изменений, незакрытые треды или блокирующие Issue. Сигналы могут пересекаться: один PR не становится несколькими PR только потому, что у него несколько проблем.

Для PR основной показатель «Готово» означает уже влитые PR. Готовность к слиянию показывается отдельно; её условия и достаточные данные ещё предстоит определить. Для review нужен сигнал, помогающий заметить, где давно ждут ответа на последнее сообщение. Его порог и способ подтвердить ожидание пока не выбраны: старый тред или много комментариев сами по себе этого не доказывают.

Метрики и графики помогают увидеть текущую работу и результаты за период, когда есть достаточные данные. Исторический график Project использует его нынешний состав репозиториев для выбранного периода. Если истории не хватает, пробел не подменяется нулём. Формула burn-down и конкретные периоды ещё открыты. [Сводка](../../specs/nodes/GITVIEW-SPEC-0047.yaml) · [Результаты](../../specs/nodes/GITVIEW-SPEC-0125.yaml) · [Ожидание ответа](../../specs/nodes/GITVIEW-SPEC-0094.yaml) · [Графики](../../specs/nodes/GITVIEW-SPEC-0013.yaml)

При переходе по сигналу важен его исходный контекст. Если сигнал возник внутри отфильтрованной области, открытая выборка сохраняет её фильтры; посторонний фильтр не сужает сигнал, возникший вне его области. Например, исторический счётчик merged, который сам включает merged PR, открывает соответствующий результат, даже если отдельный сохранённый фильтр их скрывает; сохранённая настройка при этом не переписывается. [Контекст сигнала](../../specs/nodes/GITVIEW-SPEC-0092.yaml)

## Когда данные устарели или доступ изменился

GitView хранит ранее полученные наблюдения и может показывать доступные сохранённые данные без ожидания нового ответа GitHub. Пользователь может запросить обновление вручную — pull-to-refresh там, где это подходит, или эквивалентным действием. При открытии устаревших данных приложение запрашивает обновление с учётом ограничений источника; фоновые возможности зависят от iOS и не гарантируют частоту.

Если обновление не удалось, пользователь видит соответствующую ошибку или причину и время последнего подтверждённого обновления для затронутой области, когда оно известно. Уже сохранённое не выдаётся за свежий ответ, а неполные данные — за подтверждённую пустоту. [Обновление](../../specs/nodes/GITVIEW-SPEC-0003.yaml) · [Запрос обновления](../../specs/nodes/GITVIEW-SPEC-0048.yaml)

Если GitHub явно отзывает доступ к private Repository, пока соответствующий аккаунт остаётся активным, сохранённые данные остаются видимыми как последние известные: с отметкой об отзыве и временем обновления, если оно известно. Синхронизация этого репозитория останавливается; остаётся путь разобраться с доступом или явно удалить локальные данные. При переключении с аккаунта A на B ранее сохранённые приватные данные A не показываются, но само переключение их не удаляет. Поведение после возвращения к A ещё не выбрано. [Доступ](../../specs/nodes/GITVIEW-SPEC-0019.yaml) · [Состояние подключения](../../specs/nodes/GITVIEW-SPEC-0036.yaml)

## Внешний вид и продолжение

GitView ориентируется на Apple Look: системные компоненты и цвета, SF Symbols и сдержанный Liquid Glass. Важные состояния и действия должны быть понятны не только по цвету или через жест: нужны доступные альтернативы, в том числе для масштабирования и preview. Проверка доступности на устройстве ещё впереди. [Доступность](../../specs/nodes/GITVIEW-SPEC-0017.yaml)

Лёгкий sharing доступных ссылок на объекты GitHub входит в направление продукта; делиться самим локальным Project в первой версии пока не требуется. Для новых Issue и PR согласованы форматы описания с Problem, Motivation и Expected outcome; для PR также Changes и Validation. Существующий внешний объект с другим описанием не исчезает и его текст не выдумывается. [Sharing](../../specs/nodes/GITVIEW-SPEC-0016.yaml) · [Форматы](../../specs/nodes/GITVIEW-SPEC-0010.yaml)

Скользящий preview по соседним ячейкам, календарь на самом дальнем масштабе и более глубокое погружение внутрь PR — идеи на будущее, а не обязательства первой версии. [Будущие направления](../../specs/nodes/GITVIEW-SPEC-0018.yaml)

**Ещё предстоит выбрать:** условия отдельной готовности к слиянию; порог и доказательства ожидания ответа; точную иерархию фильтров, периоды и минимальный набор графиков; детали первого запуска, sharing и некоторых случаев доступа к сохранённым данным. Технические решения о GitHub API, хранении и фоновой синхронизации также остаются для следующего проектирования. [Граница review](product-review-boundary-20261116.md)
