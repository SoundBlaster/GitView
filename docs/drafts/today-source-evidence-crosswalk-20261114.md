# Today: источники фактов и границы полноты

Рабочая сверка для [0101](GITVIEW-SPEC-0101.yaml),
[0102](GITVIEW-SPEC-0102.yaml) и [0110](GITVIEW-SPEC-0110.yaml), не выбранный
алгоритм синхронизации и не результат запроса к данным пользователя. Today
содержит незавершённую работу и подходящие объекты с событиями выбранного
локального дня; один объект не превращается в несколько карточек из-за
нескольких подходящих оснований.

| Требование | Что может подтвердить отдельный факт | Чего этого недостаточно подтвердить |
| --- | --- | --- |
| Состав Project | Подтверждённая локальная конфигурация и identity каждого Repository по 0025 и 0038. | Полномочия текущего аккаунта на каждый тип source-данных и полноту их выборки. |
| Тип и identity PR / Issue | Типизированное представление источника с source instance, подтверждённым Repository и соответствующим видом ID. | Число в другом Repository или ID другого вида само по себе не доказывает совпадение. [REST Issues](https://docs.github.com/en/rest/issues/issues#list-repository-issues) может вернуть PR с Issue ID. |
| Открытая работа | Применимое наблюдение текущего open state идентифицированного объекта. | Все открытые объекты, которые не присутствовали в этой выборке. [Issues `since`](https://docs.github.com/en/rest/issues/issues#list-repository-issues) ограничивает выдачу недавним обновлением, поэтому старый неизменённый open object может не попасть в результат. |
| Создано в течение дня | Source-supported creation instant и текущие локальные полуоткрытые границы дня. | Текущее состояние само по себе не устанавливает время создания или полноту всех объектов дня. |
| Закрыто или влито в течение дня | Подтверждённое событие с его временем; [PR `mergedAt`](https://docs.github.com/en/graphql/reference/pulls#pullrequest) и [ClosedEvent](https://docs.github.com/en/graphql/reference/issues#closedevent) — документированные ориентиры для соответствующих фактов. | Полная история для всех объектов, видимость и причина любого закрытия. Текущее состояние или `updatedAt` не заменяет событие, особенно после reopening. |
| Неотфильтрованная популяция | Достаточное evidence объединения всех применимых альтернатив в каждом выбранном Repository, его области доступа и времени. | [REST PR list](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests) и Issues list по умолчанию ограничены open; `state=all` меняет фильтр состояния, но само по себе не доказывает полноту событий или непротиворечивый snapshot. |
| Карточка и preview | Отдельно поддержанные identity, title, lifecycle, review/CI и другие выбранные поля с собственными временными и access контекстами. | Успех основного списка не подтверждает все поля, успешность проверок, пустые треды или разрешение раскрывать cached private data. |
| Полнота страниц | Свидетельства применимости источника, доступа, непрерывности и стабильности именно заявленного scope, в дополнение к завершению обхода. | [GraphQL pageInfo](https://docs.github.com/en/graphql/guides/using-pagination-in-the-graphql-api) сообщает о навигации по страницам; терминальный курсор сам по себе не является доказанным единым snapshot. |

Пример: Issue, открытая неделю назад и не менявшаяся с тех пор, всё ещё может
быть нужной в Today. Запрос Issues с `since` от начала дня не является
доказательством её отсутствия. Другая Issue могла закрыться и снова открыться
сегодня: её текущий open state поддерживает включение в Today, но без evidence
события не доказывает её включение в отдельную историческую выборку закрытий.

Остаются открыты конкретная комбинация операций, права каждого поля,
перенос и переименование Repository, документированные гарантии для
пересекающихся страниц и оценка стоимости. Последнюю пользователь просил не
превращать в предварительный подбор лимитов. Неизвестная полнота не запрещает
показывать поддержанные разрешённые объекты с видимым ограничением; она не
даёт права объявлять точное число или отсутствие остальных объектов.
