# Today: источники фактов и границы полноты

Рабочая сверка для [0101](GITVIEW-SPEC-0101.yaml),
[0102](GITVIEW-SPEC-0102.yaml) и [0110](GITVIEW-SPEC-0110.yaml), не выбранный
алгоритм синхронизации и не результат запроса к данным пользователя. Today
содержит незавершённую работу и подходящие объекты с событиями выбранного
локального дня; один объект не превращается в несколько карточек из-за
нескольких подходящих оснований.

| Требование | Что может подтвердить отдельный факт | Чего этого недостаточно подтвердить |
| --- | --- | --- |
| Состав Project | Подтверждённая локальная конфигурация и identity каждого Repository по 0025 и 0038. | Полномочия текущего аккаунта на каждый тип source-данных и полноту их выборки. |
| Тип и identity PR / Issue | Типизированное представление источника с source instance, подтверждённым Repository и соответствующим видом ID. | Число в другом Repository или ID другого вида само по себе не доказывает совпадение. [REST Issues](https://docs.github.com/en/rest/issues/issues#list-repository-issues) может вернуть PR с Issue ID. |
| Связь объекта с Repository | Типизированные GraphQL [Issue](https://docs.github.com/en/graphql/reference/issues#issue) и [PullRequest](https://docs.github.com/en/graphql/reference/pulls#pullrequest) предоставляют поле `repository`; его Node ID можно сопоставить с ранее подтверждённой identity при наличии свидетельства 0080. | Имя в URL, один успешный HTTP response или `headRepository` у PR из fork не подтверждают принадлежность исходному Project. Недоступное поле и неподтверждённый alias оставляют связь неизвестной. |
| Открытая работа | Применимое наблюдение текущего open state идентифицированного объекта. | Все открытые объекты, которые не присутствовали в этой выборке. [Issues `since`](https://docs.github.com/en/rest/issues/issues#list-repository-issues) ограничивает выдачу недавним обновлением, поэтому старый неизменённый open object может не попасть в результат. |
| Граница recent Issue candidates | REST repository Issues `since` описан как обновление **после** указанного времени, а GraphQL [`IssueFilters.since`](https://docs.github.com/en/graphql/reference/issues#issuefilters) — в это время **или позже**. | Одинаковый timestamp в этих запросах не задаёт одну и ту же границу. Оба фильтра относятся к обновлению, а не непосредственно к событию закрытия; равенство границы и отсутствие в ответе не доказывают полноту обхода. |
| Создано в течение дня | Source-supported creation instant и текущие локальные полуоткрытые границы дня. | Текущее состояние само по себе не устанавливает время создания или полноту всех объектов дня. |
| Закрыто или влито в течение дня | Подтверждённое событие с его временем; [PR `mergedAt`](https://docs.github.com/en/graphql/reference/pulls#pullrequest) и [ClosedEvent](https://docs.github.com/en/graphql/reference/issues#closedevent) — документированные ориентиры для соответствующих фактов. | Полная история для всех объектов, видимость и причина любого закрытия. Текущее состояние или `updatedAt` не заменяет событие, особенно после reopening. |
| Неотфильтрованная популяция | Достаточное evidence объединения всех применимых альтернатив в каждом выбранном Repository, его области доступа и времени. | [REST PR list](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests) и Issues list по умолчанию ограничены open; `state=all` меняет фильтр состояния, но само по себе не доказывает полноту событий или непротиворечивый snapshot. |
| Карточка и preview | Отдельно поддержанные identity, title, lifecycle, review/CI и другие выбранные поля с собственными временными и access контекстами. | Успех основного списка не подтверждает все поля, успешность проверок, пустые треды или разрешение раскрывать cached private data. |
| Полнота страниц | Свидетельства применимости источника, доступа, непрерывности и стабильности именно заявленного scope, в дополнение к завершению обхода. | [GraphQL pageInfo](https://docs.github.com/en/graphql/guides/using-pagination-in-the-graphql-api) сообщает о навигации по страницам; терминальный курсор сам по себе не является доказанным единым snapshot. |

Пример: Issue, открытая неделю назад и не менявшаяся с тех пор, всё ещё может
быть нужной в Today. Запрос Issues с `since` от начала дня не является
доказательством её отсутствия. Другая Issue могла закрыться и снова открыться
сегодня: её текущий open state поддерживает включение в Today, но без evidence
события не доказывает её включение в отдельную историческую выборку закрытий.

Остаются открыты конкретная комбинация операций, права каждого поля,
перенос и переименование Repository, документированные гарантии для
пересекающихся страниц и оценка стоимости. Последнюю пользователь просил не
превращать в предварительный подбор лимитов. Неизвестная полнота не запрещает
показывать поддержанные разрешённые объекты с видимым ограничением; она не
даёт права объявлять точное число или отсутствие остальных объектов.

## Кандидат mapping для отдельных GraphQL facts

На следующем проходе 0101 уточняет документированные enum значения:
PR `OPEN` / `CLOSED` / `MERGED` и Issue `OPEN` / `CLOSED` — разные
типизированные множества. У Issue `stateReason` хранится отдельно, а
`ClosedEvent.stateReason` относится к конкретному событию. Например, текущий
`REOPENED` и более ранний `NOT_PLANNED` не заменяют друг друга. Неизвестное
новое enum значение не превращается в один из известных статусов.
[GitHub PullRequestState](https://docs.github.com/en/graphql/reference/pulls#pullrequeststate),
[IssueState и IssueStateReason](https://docs.github.com/en/graphql/reference/issues#issuestatereason),
[ClosedEvent](https://docs.github.com/en/graphql/reference/issues#closedevent).
Это mapping документированных полей, не проверка доступа, query, полноты
timeline или выполняющегося приложения.

[0101](GITVIEW-SPEC-0101.yaml) теперь описывает документированный кандидат:
типизированные `Issue` / `PullRequest` с подтверждённым source и Repository,
Node ID и контекстом доступа; `createdAt` для создания, наблюдаемый `state`
для lifecycle, PR `mergedAt` для времени merge. Для конкретного закрытия может
использоваться связанное с объектом событие `ClosedEvent` с его `createdAt`
и `id`. [GitHub: Issues и события](https://docs.github.com/en/graphql/reference/issues),
[GitHub: PullRequest](https://docs.github.com/en/graphql/reference/pulls).

Это достаточное **направление для отдельных успешно полученных фактов**, а не
обещание одного полного query или достаточности прав GitHub App. `closedAt`
и пустой timeline сами по себе не устанавливают всю историю переоткрытий;
`updatedAt` и время получения не заменяют время события. Отдельно требуется
обосновать обнаружение всех потенциальных объектов, pagination, ограничения
доступа и применимость temporal coverage. При их отсутствии маршрут может
показывать разрешённые подтверждённые факты с ограничением полноты.

[0102](GITVIEW-SPEC-0102.yaml) уточняет кандидат операций: GraphQL
`Repository.issues` с отдельными запросами для открытых без `since` и для
недавно обновлённых Issue, а PR — отдельная `Repository.pullRequests`
connection со своими аргументами. Это маршруты обнаружения кандидатов,
а не доказательство полного Today, прав GraphQL или стабильности страниц.

При последующем проходе 0102 выбрал эту схему как **рабочее направление** для
первой версии: отдельные open и recent portions по каждому типу и Repository,
типизированные факты 0101 и отдельное получение подтверждённых close events,
когда они нужны. Для recent PR используется отдельная all-state connection
с доступной сортировкой по обновлению; это не доказанная полная выборка
событий. Не выбраны состав окончательного query, конкретные размеры страниц,
стоимость, field permissions или гарантия completeness. Если часть источника
недоступна, разрешённые подтверждённые карточки остаются полезными с явным
ограничением. Основание: [GitHub Repository GraphQL](https://docs.github.com/en/graphql/reference/repos),
[Issues](https://docs.github.com/en/graphql/reference/issues),
[Pull requests](https://docs.github.com/en/graphql/reference/pulls).


## Передача фактов в Today и сводки

Сверка автором на рабочем ontology draft.12; это описание существующих
candidate contracts, не проверка реального GitHub или окончательная схема API.

| Участок | Что передаётся дальше | Что остаётся самостоятельным |
| --- | --- | --- |
| 0101 → 0116 | Типизированная identity и поддержанные факты PR/Issue с source, Repository и временем или ограничением. | Неопределённая identity не превращается в карточку; время сопоставления не становится временем source observation. |
| 0102 → 0116 / 0110 | Отдельное evidence охвата population, применимое к scope, периоду и фильтрам. | Классификация найденных объектов не доказывает, что найдены все; точный source aggregate сам по себе не перечисляет карточки. |
| 0116 → 0110 | Подготовленные факты конкретного объекта и их applicability; результаты получения, сохранения и доступности передаются отдельно. | Исход сохранения не доказывает source success; факт из ответа не обязательно переживёт restart. |
| 0110 → сборка маршрута | Match, non-match или unknown для конкретной подтверждённой identity в захваченном контексте. | Сборка независимо применяет coverage, актуальные ограничения доступа и состояние фильтров. |
| 0116 / 0102 → 0119 | Поддержанные входы одной названной метрики с unit, scope, временем и coverage. | Вычисленное значение, даже точное, не гарантирует набора идентификаторов для перехода по сигналу по 0092. |

Рабочее направление получения кандидатов в 0102 — GraphQL connections по
отдельным open/recent целям. Оно не является окончательным query или
доказательством полной популяции. Открыты источник и применимость событий,
права отдельных полей, сопоставление типов identity и гарантии coverage; их
нельзя закрыть одним `checked` или искусственным примером. Точные бюджеты и
число запросов не выбираются на этом проходе.
