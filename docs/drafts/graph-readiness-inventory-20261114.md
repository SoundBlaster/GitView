# GitView: инвентаризация готовности графа

Снимок охватывает 102 candidate specs, включая 47 структурных листьев по
`refines`. Все 102 имеют `idea / pre_canonical`; каждый узел, кроме корня,
достигает 0001 по `refines`. У всех объявленных ссылок есть цели; циклов в
`refines`, `depends_on` и их объединении не обнаружено. Это структурные факты,
а не доказательство полноты отношений или готовности к реализации.

[Машинный снимок](evidence/autonomous-goal-graph-readiness-inventory-20261114.json)
содержит SHA каждого кандидата и для каждого листа — прямые рёбра, число
достижимых узлов, сценарии по полям и исходный список `unresolved`. Его можно
воспроизвести [скриптом](evidence/graph-readiness-inventory.py), указав новый
путь вывода. Скрипт не оценивает смысл, не классифицирует каждый unresolved как
blocker и не считает число сценариев мерой покрытия. Достижимость показывает
только рёбра, записанные в YAML.

| Узел | Наблюдение | Последствие для реализации |

| 0071 | Recovery и durable evidence сформулированы, но commit granularity, operation identity и механизм восстановления ещё не выбраны. | Контракт важен для нижележащих storage-листьев; одного этого узла недостаточно для однозначной реализации. |
| 0075 | Определено разрешение конфликтов жестов и прерываний на уровне требований; точные density, тайминги и нативное поведение открыты. | Потребуются конкретизация платформенного контракта и проверки на устройстве; сейчас это не завершённый UIKit/SwiftUI design. |

| 0098–0100 | Выбрана кандидатная схема GitHub App, но ещё не установлены callback, применимость разрешений к фактическим операциям и UX установки. | До реализации connection boundary нужны конкретные source и platform решения; реальные интеграционные проверки последуют отдельно. |
| 0101–0102 | Предусмотрены нормализация и честное ограничение полноты, но отсутствует выбранный source-backed способ получить необходимые поля и доказать покрытие. | Можно продолжать верхнеуровневый граф, но конкретный adapter нельзя считать специфицированным до реализуемого контракта. |

Это выборочная содержательная оценка, а не независимый аудит всех 47 листьев.
Не все перечисленные открытые вопросы одинакового типа: некоторые требуют
проектного решения до кода, другие — подтверждения средствами реального
компонента или платформы после появления реализации. Текущий статус `idea` и
структурная проверка сами по себе не заменяют этот разбор.

## Исправленные зависимости и следующий проход

0096 и 0097 явно зависят от 0102: route composition и история метрик используют
сведения о покрытии. [Candidate и ontology advisory](evidence/autonomous-goal-ontology-check-readiness-edges-20261114.json)
для обоих изменённых узлов прошли без findings, gaps и warnings; compiler
provenance не подтверждён, semantic approval не установлен.

Следующий проход должен оценить оставшиеся листья по критериям: достаточно ли
определены входы и результаты, ошибки и ограничения, внешние зависимости,
различимые критерии приёмки и граница ответственности; затем связать недостающие
предварительные решения с ветвями и отделить будущую интеграционную проверку
от отсутствующей спецификации. Особенно важны 0071 и конкретные source contracts,
потому что их неопределённости затрагивают несколько основных маршрутов.
