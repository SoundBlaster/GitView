# Repository identity: перенос и review

На базе GitView `523f1057d5114f800350015721bdf1805fe5e550` подготовлен
[GITVIEW-SPEC-0002](../../specs/nodes/GITVIEW-SPEC-0002.yaml), уточняющий
канонический корень 0001. Сохранены выбранные владельцем непрерывность при
подтверждённых rename и transfer и примеры с numeric REST ID в пределах одного
GitHub, повторным использованием адреса и ответом 404. Исходный
[черновик](GITVIEW-SPEC-0002.yaml) остаётся неканоническим источником;
детали его контрактов и ontology bindings автоматически не принимаются.

Независимый read-only reviewer сравнил вариант SHA-256
`76d72279097cbd667aa63613b66a1914a275e6697116e5e115e2614849c290b4`
с исходным решением, черновиком, родителем и составом Project. Он обнаружил,
что выбранные примеры ID были ошибочно оставлены открытыми, а `can present`
ослабляло обязанность обновить подтверждённый текущий адрес. Автор вернул
выбранные примеры и обязательное обновление, явно зафиксировал 404 и сохранил
ограничения по порядку наблюдений и доступу. При повторной проверке reviewer
сообщил scoped PASS для итогового SHA-256
`1cbedb3375dcb85d7dfa47c235a21f17d5d12de0b09b3f7822ad8a3c2983a757`.

Установленные форматтер и YAML lint прошли; candidate check проверил структуру
сохранённого черновика, а `next-move` обнаружил узел в графе и рекомендовал
дальнейшее уточнение с review. Это не проверка фактического transfer в GitHub,
не подтверждение полноты данных и не готовность к реализации. Способ получения
source evidence, политика доступа и технические детали ещё требуют уточнения.
