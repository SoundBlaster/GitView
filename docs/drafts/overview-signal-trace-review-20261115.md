# Сверка сигналов обзора и перехода к PR

Авторская проверка черновиков на текущем рабочем дереве. Это не исполнение
сценариев, не проверка GitHub и не утверждение всего графа. Фиксируется
прослеживаемость одной ветви, а не полнота всех сигналов продукта.

| Звено | Основание и ограничение |
| --- | --- |
| Отдельные факты | [0011](GITVIEW-SPEC-0011.yaml), [0061](GITVIEW-SPEC-0061.yaml), [0062](GITVIEW-SPEC-0062.yaml): CI, assessment, requests и threads сохраняют независимые контексты; обновление одного не подтверждает остальные. Источник и применимость ещё требуют проверки. |
| Сводка Project | [0057](GITVIEW-SPEC-0057.yaml), `review_predicate_independence` и `independent_review_signal_destinations`: разные условия подсчитываются отдельно; частичное покрытие не становится точным итогом. [0089](GITVIEW-SPEC-0089.yaml) нужен для применимости входов и теперь явно указан в prerequisites 0057. |
| Показ и обновление | [0047](GITVIEW-SPEC-0047.yaml), `mixed_refresh_with_prior_data`: время и результат обновления одной категории не заменяют наблюдение другой. Ограничения видны в доступном интерфейсе. |
| Переход к выборке | [0092](GITVIEW-SPEC-0092.yaml), `intersect_thread_and_ci_signals` и `unproven_destination_traversal`: сохраняются scope и условие; число проверок или тредов не приравнивается к числу PR, а неполный список не объявляется исчерпывающим. |
| Открытый объект | [0093](GITVIEW-SPEC-0093.yaml), `stale_ci_new_title`: более свежее название не делает CI прежней ревизии актуальным. Preview и карточка сохраняют собственные контексты данных. |

Проверенные сценарии согласуются по единицам и ограничениям в заявленных
условиях. Это не доказывает, что любую связку этих контрактов можно исполнить:
фактическое source mapping, права, совместимость разных наблюдений и native
presentation остаются открытыми. Не добавляем обратное ребро 0057 → 0092:
0092 уже зависит от 0057, и такое ребро создало бы цикл. Обзор собранного
маршрута обязан учитывать оба узла, а не только prerequisite closure 0057.
