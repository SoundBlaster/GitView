# Today: кандидат контракта сборки состояния маршрута

Авторское уточнение [0115](GITVIEW-SPEC-0115.yaml), `idea / pre_canonical`. Маршрут связывает Project, накопленные наблюдения, [решение для одного объекта](today-decision-boundary-candidate-20261115.md), coverage и эффекты. Это проверяемый информационный контракт, не Swift API, реализация экрана или утверждение о полном source snapshot.

## Независимые части состояния

| Компонент | Сохраняемое значение и граница | Не заменяет |
| --- | --- | --- |
| Route context | Идентичность route и Project, выбранный scope, подтверждённое или неопределённое membership, captured local day, filters, density и origin. Новая оценка сохраняет свою идентичность. | Текущие исходные данные, разрешение и историю всех предыдущих маршрутов. |
| Saved configuration | Результат scoped Project read и допустимые данные текущей конфигурации. Unreadable или partial не объявляется пустым Project. | Результат GitHub refresh или подтверждение прав на факты. |
| Candidate observations | Независимо интерпретируемые permitted факты, source, identity, event/observation time, revision и контекст доступа; локально восстановленные и временные факты различаются. | Полное множество source объектов и успешную durable запись. |
| Decisions | Match, non-match или unknown отдельно для каждого подтверждённого допустимого typed candidate и captured evaluation; integration no-result отдельно. | Coverage коллекции, source error или подтверждённую пустоту Project. |
| Coverage | Отдельная оценка для каждой применимой части scope, типа, условия и reference; отображаемый итог допускается только в поддержанном контексте. | Число отсутствующих карточек, grant или точный источник ошибки. |
| Effect outcomes | Read, source attempt, field limitation, retention и history effect с отдельными идентичностями, временем, состоянием и безопасной причиной, когда она поддержана. | Успех соседнего эффекта; факт, что GitHub ничего не изменил, если результат неизвестен. |
| Presentation and disclosure | Разрешённые confirmed matches и inspectable uncertainty, отдельная общая limitation и допустимые действия; перед выводом действует текущий disclosure. | Раскрытие ограниченных identity, count, ссылки или причины ради объяснения неопределённости. |

Это смысловые группы, не обязательная структура памяти, набор типов или одна транзакция. Значения с несовместимыми scope, subject, временем или revision не сливаются для получения точного числа. Одна подтверждённая identity может получать несколько применимых наблюдений, но не несколько карточек; конфликтующая association не разрешается совпадением названия.

## Переходы и наблюдаемый результат

| Событие | Правило сборки |
| --- | --- |
| Открытие или восстановление | Прочитать Project и допустимые сохранённые факты независимо. Сохранённые значения и ограничения получают исходные времена; отдельное право на background/foreground refresh проверяется по 0048. Открытие не является успешным обновлением. |
| Завершилась часть source attempt | Сопоставить факты с исходным request context и сохранить независимые field и coverage outcomes. Переоценить текущий route только при совместимости identity, выбора, дня и доступа. Поддержанный in-memory факт может быть показан, пока допустим, даже если запись не подтвердилась; UI не обещает его recovery. |
| Локальная запись завершилась или её ответ потерян | Показать только подтверждённый исход соответствующей операции; неопределённый исход сверять с тем же binding. Receipt не заменяет чтение после перезапуска; локальный сбой не превращает source success в source failure. |
| Изменились фильтр, день или членство | Создать соответствующий новый контекст оценки. Сохранить совместимые факты с прежними временами; не переносить старую coverage на новый scope. Устаревший результат может сохраниться в собственной области, но не заменяет активный route. |
| Доступ ограничен после начала работы | До публикации пересмотреть разрешённые факты, результаты, preview и доступные действия. Поздний ответ не отменяет известного ограничения; ограниченный объект или его число не раскрываются через unknown-раздел. |
| Selection пуста | Различать подтверждённо пустую популяцию при достаточном evidence, отсутствие подтверждённых matches при неполном coverage и намеренно исключающий фильтр. Ни один из них не обозначает автоматически два других. |

Отдельный неподтверждённый или отложенный scope может сосуществовать с показанными фактами. Индикация последнего обновления относится к тому scope, который действительно поддержан; свежий title не делает свежими review, CI или весь Project. Ошибка и безопасное действие повторной попытки остаются обнаружимыми, если это допустимо по disclosure.

## Проверяемые сквозные случаи

1. P содержит A и B; X из A подтверждён, покрытие B отсутствует. Экран может показать X и неполноту, но не точный P total и не число неизвестных объектов.
2. В refresh один факт поддержан источником, а его local retention indeterminate. До завершения сессии факт может быть показан с limitation; после restart нужен собственный recoverable read, а не один receipt.
3. Старый запрос P(A, B) завершается после изменения P на (A, C). Его факты сохраняют исходную область; активный маршрут не получает B как текущего member и не считает C покрытым.
4. Во время preview факта возникает известный запрет. Повторная проекция и действия не раскрывают ограниченные данные, даже если завершился старый запрос или cached read.
5. Все lifecycle-фильтры намеренно сняты: экран различает результат фильтра и наблюдаемую пустоту источника; очистка фильтров восстанавливает unrestricted по 0110.

Будущие тесты используют DI для source, storage, clock, access и scheduler, фиксируют состояние и видимые результаты, не привязываясь к внутренней очереди вызовов. Проверки настоящего GitHub, restart provider и нативных жестов остаются отдельными уровнями evidence. Конкретные Swift signatures, ошибки, акторная изоляция и механизм обновления UI не выбраны.
