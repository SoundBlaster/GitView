# Первое подключение и доступ: независимая сверка

На `e529232` независимый read-only reviewer сопоставил узлы 0003, 0005, 0019
и 0022. Прямых противоречий между проверенными узлами не нашёл: выбор
Repository, сохранение Project и получение работы различаются; network failure
не приравнивается к отказу GitHub; невыбранная default association не выдана
за решение владельца.

Остаются продуктовые вопросы, влияющие на наблюдаемое поведение:

1. Что показывать из сохранённых private данных после explicit denial,
   disconnect, смены аккаунта и при offline; Project metadata и содержание
   могут требовать разных правил. Вопрос об explicit denial задан владельцу.
2. Что для пользователя означает завершённый disconnect, включая уже
   запущенное обновление и неопределённый результат удаления credential.
3. При default setup для Repository, уже входящего в несколько Projects,
   нужно ли предлагать существующий Project или создавать ещё один; исход
   неясного сохранения нельзя молча превратить в safe duplicate.

Эти пробелы не отменяют описанный условный успешный маршрут первого запуска.
Точные API, database и retry timing остаются техническими вопросами и не
устанавливаются этим review. Ни один узел не объявлен готовым к реализации.
