# PullRequest: заготовка для выбора

Статус: предложение агента для обсуждения. Все пункты ниже — кандидаты;
галочки оставлены пустыми. Это не принятые требования приложения или изменения
ontology package. Можно выбрать блок целиком или отдельные номера.

Кандидатное значение: запрос на рассмотрение предлагаемых изменений кода и их
возможное включение в целевую ветку. Формулировка также требует выбора.

## A. Идентификация и описание

- [ ] A1. Идентификатор в источнике и номер PR в контексте репозитория.
- [ ] A2. Название.
- [ ] A3. Описание / текст.
- [ ] A4. Ссылка на первоисточник.

## B. Состояние PR

- [ ] B1. Жизненный цикл: открыт, закрыт без merge, merged.
- [ ] B2. Признак draft отдельно от жизненного цикла.
- [ ] B3. Метки / labels как дополнительные характеристики.

B1 — кандидатный набор по GitHub; это ещё не полная state machine переходов,
команд, условий и акторов. Draft не образует с review и CI одну общую шкалу.

## C. Контекст и участники

- [ ] C1. Целевой GitHubRepository.
- [ ] C2. Исходная и целевая ветки, ссылка на текущую ревизию изменений.
- [ ] C3. Автор / создатель PR как роль участника.
- [ ] C4. Запрошенные reviewers.
- [ ] C5. Связанные Issue.

Это кандидаты ссылок и ролей, а не скалярные поля или объявленные типы отношений
в пользовательском смысле Ontology. Их происхождение через действия надо
рассматривать отдельно. Автор PR не автоматически User приложения или coding
agent. Ссылка на Issue сама по себе не устанавливает мотив актора. Названия
веток и технических ссылок не вводят новые ontology entities автоматически.

## D. Review

- [ ] D1. Доступная итоговая оценка review со смыслом, заданным источником.
- [ ] D2. Связанные ReviewThread.
- [ ] D3. Число тредов и число незакрытых тредов как отдельные метрики.

Отсутствие доступной оценки, отсутствие reviews и требование review различаются.
Итоговая оценка не заменяет состояние отдельных тредов.

## E. CI

- [ ] E1. Связанные CIStatus / результаты проверок для определённой ревизии.
- [ ] E2. Связанные прогоны и их состояние: например, ожидает, выполняется, завершён.
- [ ] E3. Результат завершённого прогона: например, успех, ошибка, отмена.
- [ ] E4. Число прогонов как метрика.

Списки E2/E3 иллюстративные, не исчерпывающий enum GitHub. Итоговый CI и отдельные
прогоны не тождественны; неизвестность данных не означает успех или отсутствие
проверок. Связь результата с ревизией нужна для понимания, к чему он относится.

## F. Объём предлагаемых изменений

- [ ] F1. Число добавленных и удалённых строк отдельно.
- [ ] F2. Число изменённых файлов.
- [ ] F3. Число коммитов.

Это измерения с конкретной областью подсчёта, а не стадии жизненного цикла PR.

## G. Время

- [ ] G1. Время создания и последнего обновления.
- [ ] G2. Время закрытия или merge, когда применимо.
- [ ] G3. Время получения наблюдения и его источник.

Времена предметных событий отличаются от времени наблюдения GitView. Точный
состав достаточного состояния и способ представления неполных данных открыты;
эту заготовку нельзя считать полным eventcore:StateSnapshot.

## Граница следующего шага

После выбора уточняем смысл, типы значений, роли, допустимые состояния и
неизвестность для выбранных пунктов. Отдельно спецификации GitView определят
получение, обновление, вычисление и показ этих данных. «Готов к merge»,
«застрял» и «требует внимания» требуют собственных правил и пока не объявлены
исходными состояниями PR. Реализация просмотра внутреннего diff не предлагается.

Источник для сверки GitHub lifecycle / draft / review:
[GitHub GraphQL: Pull requests](https://docs.github.com/en/graphql/reference/pulls).
Остальная группировка — предложение агента на основе беседы, а не перенос
API-схемы в онтологию. Запрос пользователя: conversation:gitview/excerpt-33.
