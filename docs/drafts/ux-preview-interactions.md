# Предпросмотр карточек: Peek and Pop и скользящий preview

Статус: пользователь запросил Peek and Pop по long tap для первой версии
(`conversation:gitview/excerpt-43`). Скользящий rich preview предложен им как
дальнейшее развитие. Последующее «Вероятно он активируется через long press»
(`excerpt-44`) — рабочая гипотеза активации скользящего режима, не окончательный
gesture contract. Уточнения поведения ниже — предложение агента.

Это UX над существующими Project, GitHubRepository, PullRequest и Issue;
новые ontology entities «Бабл» или «Preview» не вводятся. Код не создаётся.

## Первая версия: Peek and Pop

- Long press на карточке открывает её увеличенный предпросмотр поверх сетки.
- Preview позволяет прочитать больше данных без перехода внутрь объекта.
- Явное раскрытие preview / действие «Открыть» ведёт в согласованный обзор
  того же объекта. Способ commit-перехода проверим в нативном прототипе.
- Закрытие возвращает к той же сетке, области, фильтру, позиции и плотности.
- Предлагаемые действия: открыть объект; перейти на GitHub там, где есть
  первоисточник; системный sharing. Состав меню ещё требует согласования.

Визуальный референс пользователя — приложенный скриншот Photos: крупный preview
над контекстным меню и приглушённая сетка за ним. Референс касается поведения
и визуальной иерархии. Команды Copy, Duplicate, Hide и другие со скриншота не
переносятся автоматически в GitView. Копия исходного изображения:
[peek-pop-reference.jpg](assets/peek-pop-reference.jpg).

## Далее: скользящий rich preview

Пользователь хочет один универсальный бабл с подробностями объекта под пальцем,
перемещающийся от ячейки к ячейке без перехода в объекты. Hover рассматривается
для устройств с указателем.

Предлагаем единый вход, сохраняя неопределённость пользовательского «вероятно»:

```text
long press на карточке
  → preview выбранного объекта
  → палец остаётся на месте: читаем его подробности
  → палец движется по сетке: тот же бабл показывает другую карточку
  → явное «Открыть»: переход в текущий объект
```

Обычное движение без предварительного удержания сохраняет прокрутку сетки.
После активации скользящего режима движение выбирает объект, а не одновременно
прокручивает и выбирает. Поведение возле края экрана и автопрокрутку пока
не определяем; их надо проверить отдельно. Pinch должен завершать preview
предсказуемо, не запускать конкурирующие переходы.

На отпускание пальца предлагаем закрывать скользящий preview без навигации;
конкретный способ удержать его для чтения и выполнить Pop надо проверить
прототипом. Не обещаем, что стандартное контекстное меню и будущий скользящий
режим имеют одинаковый lifecycle отпускания. Первую версию не блокируем
реализацией будущего режима.

## Общая форма, содержимое зависит от объекта

| Объект | Подробности в preview — предложение |
| --- | --- |
| Project | Название, состав/охват репозиториев, PR/Issue и сигналы внимания |
| Repository | Owner/name, открытая работа, review/CI, актуальность |
| PR | Полное название и номер, review, CI-счётчики, треды, размер изменений; короткий фрагмент Problem/Motivation при наличии |
| Issue | Полное название и номер, состояние/причина, назначения, счётчики обсуждения/sub-issues и blockers; короткий фрагмент Problem/Motivation |

Бабл имеет общий визуальный каркас, но не требует общей доменной метасущности.
Он использует уже выбранные поля, не вводит просмотр содержимого ReviewThread,
diff или логов. Текст не генерируется для заполнения отсутствующих сведений.

## Правила непрерывности — предложение

- В каждый момент виден один preview с однозначной привязкой к подсвеченной
  карточке. Смена карточки обновляет его содержимое, не создавая очередь окон.
- Бабл расположен так, чтобы палец не закрывал текст; адаптируется к краям
  экрана и крупному шрифту. «Под пальцем» означает выбор объекта, а не требование
  разместить текст буквально под точкой касания.
- Фильтры и порядок сетки сохраняются во время жеста. На промежутке между
  ячейками не подменяем объект случайным соседом; точный порог выбора проверим.
- Медленный ответ источника не должен показывать данные предыдущего объекта
  под заголовком нового. Неполнота/свежесть данных остаётся видимой.
- Preview и Pop не выполняют merge, approve или другие действия записи.
- Доступный способ открыть preview/обзор нужен без длинного удержания, pan
  и hover. Механика VoiceOver и Reduce Motion входит в проверку прототипа.

## Нативный ориентир и границы проверки

Для первой версии ориентируемся на системное контекстное меню с preview и
переходом из preview. Apple описывает конфигурацию preview и обработку его
commit в `UIContextMenuInteractionDelegate`:
[preview configuration](https://developer.apple.com/documentation/uikit/uicontextmenuinteractiondelegate/contextmenuinteraction(_:configurationformenuatlocation:)),
[preview action](https://developer.apple.com/documentation/uikit/uicontextmenuinteractiondelegate/contextmenuinteraction(_:willperformpreviewactionformenuwith:animator:)).

Наличие этих API не подтверждает готовую поддержку скольжения между ячейками.
Необходимость custom overlay или UIKit bridge для будущего режима надо
проверить; архитектура и deployment target этим черновиком не выбираются.
Приоритет Apple Look и минимум custom components сохраняется.

## Следующий ограниченный шаг

В визуальном прототипе первой версии добавить long press, preview и Pop
из сетки; показать возврат. Скользящий preview проверить отдельным сценарием
long press → движение через три соседние ячейки → отпускание, включая текст,
который не перекрывается пальцем. Этот сценарий ещё не реализован.
