# GitView: счётчики сводки и переходы к объектам

Сверка согласованной [сводки Project](project-summary-proposal.md) с
[0057](GITVIEW-SPEC-0057.yaml), [0092](GITVIEW-SPEC-0092.yaml) и
[0110](GITVIEW-SPEC-0110.yaml). Условия и точные слова интерфейса — рабочие
уточнения агента. Все значения сохраняют область, время, доступ и покрытие.

| Сигнал сводки | Единица сигнала | Что открывает |
| --- | --- | --- |
| Open PR / draft PR | Различные открытые PR; draft — их подмножество. | PR той же области с выбранным open и, для draft, draft условием. |
| Open Issues | Различные открытые Issue. | Issues той же области с условием open. |
| Failed CI | Различные open PR хотя бы с одной подходящей записью категории failure; число Repository — отдельная величина. | PR с тем же условием, а не отдельные проверки и не Issues. Timeout не переименовывается в failed test. |
| Review requested / changes requested | Различные open PR с соответствующим независимо установленным review условием. | PR с именно этим условием; отсутствие открытых threads само по себе его не отменяет. |
| Unresolved review threads | Threads и затронутые open PR — два разных счётчика. | Различные PR, содержащие подходящий thread; пять threads могут вести к двум карточкам. |
| Blocked Issues | Различные open Issues с подтверждённым открытым direct blocker. | Эти Issues; PR и сам blocker не становятся результатами только потому, что участвуют в связи. |
| Merged PR / closed Issues за период | События либо различные затронутые объекты — единица указывается отдельно. | Различные PR или Issues с тем же событием и периодом; event count может отличаться от количества карточек. |

Внутри одного filter facet выбранные категории объединяются; разные активные
facets пересекаются. PR-only условие исключает Issue по типу области, а не
приписывает ему «здоровый CI»; симметрично для Issue-only blocker. Неизвестное
применимое состояние остаётся неизвестным. Исторический сигнал сохраняет свой
период и не подменяется динамическим Today. Переход и последующее изменение
фильтра сохраняют исходный контекст сигнала отдельно от текущей выборки.

Опциональная выборка checks-and-review-passed не включена в этот каталог как
готовый предикат: её условия по-прежнему не выбраны и её нельзя выдавать за
merge readiness. Наличие этой таблицы не доказывает, что GitHub предоставил все
нужные данные или что UI и переходы реализованы.
