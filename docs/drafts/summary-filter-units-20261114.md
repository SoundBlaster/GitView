# GitView: счётчики сводки и переходы к объектам

При повторной сверке родителя 0047 с 0092 уточнено, что одинаковые predicate
и Project scope не требуют одинакового времени наблюдения. После обновления
destination может показывать другой результат с собственным временем и coverage;
исходный signal сохраняет свой контекст. Это разрешение текстового расхождения,
не результат работы GitHub или нативного интерфейса.

## Независимые review-сигналы

[0062](GITVIEW-SPEC-0062.yaml) уточняет три независимых факта: source
review decision, запрос конкретному reviewer и unresolved threads. Например,
`REVIEW_REQUIRED` может оставаться значимым при пустом списке запрошенных
reviewers; его нельзя прибавлять к числу явных запросов. У `reviewDecision`
nullable тип, но отсутствие значения само по себе не объясняет причину и не
доказывает approval. Тред, одновременно outdated и unresolved, остаётся в
счётчике всех unresolved, пока пользователь явно не применил отдельный фильтр.

Новый head не обновляет старый review или thread state автоматически. Частичный
ответ и отдельные времена наблюдений сохраняются; объединённый знак approval и
отсутствия вопросов не показывается без нужных свидетельств. Эти правила не
обещают мердж или воспроизведение GitHub UI. GitHub документирует поля и enum
в [GraphQL Pull requests](https://docs.github.com/en/graphql/reference/pulls),
но этим не установлены полнота выборки или права конкретного запроса.

[Candidate checks](evidence/autonomous-goal-candidate-check-review-semantics-20261114.json)
и [ontology advisory с графом](evidence/autonomous-goal-review-semantics-20261114.json)
двух узлов прошли структурно; реальные review данные, UI и policy не проверены.

## От сигнала к выборке

[0092](GITVIEW-SPEC-0092.yaml) использует результат расчёта 0119 как контекст
сигнала: его condition, unit, scope, membership basis, время и ограничения.
Сам count не считается списком составляющих PR или Issues. Для destination
нужны отдельно подтверждённые object identities и факты; при их отсутствии
доступно объяснение ограничения и безопасный путь обновить данные или вернуться.
Если signal и destination рассчитаны в разные моменты, даже совпадающие числа
не доказывают, что их состав одинаков.

Исправлено направление dependency: навигация 0092 зависит от чистого решения
0119, а 0119 не зависит от навигации. [Снимок проверки](evidence/autonomous-goal-signal-origin-aggregation-20261114.json)
подтверждает это для 119 candidates; отсутствующих целей, циклов и несвязанных
с корнем узлов нет. Candidate checks и ontology advisory двух узлов прошли
структурно; фактические source, UI, privacy и native navigation не выполнялись.

## Граница вычисления и неполные данные

[0119](GITVIEW-SPEC-0119.yaml) предлагает чистое решение для одной метрики в
заданном Project, Repository или уникальном portfolio scope. Результат
различает полное значение в подтверждённом контексте, допустимое наблюдаемое
подмножество и недоступное или неопределённое значение. Например, три
подтверждённые Issue Repository A могут оставаться полезным A-only результатом,
когда B не наблюдался, но не становятся точным общим числом Project. Отдельно
известное число PR не подтверждает полноту CI. Общее Repository учитывается в
каждом содержащем его Project, а уникальный portfolio считает его один раз.

Для каждой метрики необходимы её собственные identity, predicate, время,
coverage и право раскрытия. Прошлый частичный результат не объявляется
автоматической нижней границей текущего значения. Один подтверждённый failure
может поддержать наблюдаемый положительный PR при неполных checks, но отсутствие
увиденного failure не доказывает отсутствие ошибок. Значения, раскрывающие
ограниченные данные, не становятся допустимыми оттого, что их ранее вычислили.

Это кандидат правила, а не результат вычисления GitView. [Снимок графа](evidence/autonomous-goal-summary-aggregation-graph-20261114.json)
содержит 119 узлов и 53 структурных листа, без отсутствующих целей, циклов и
узлов без пути `refines` к корню. [Candidate checks и ontology advisory](evidence/autonomous-goal-ontology-check-summary-aggregation-20261114.json)
для 0043 и 0119 прошли структурно; source mapping, типы Swift, фактическая
конфиденциальность и тесты приложения не проверены.

Сверка согласованной [сводки Project](project-summary-proposal.md) с
[0057](GITVIEW-SPEC-0057.yaml), [0092](GITVIEW-SPEC-0092.yaml) и
[0110](GITVIEW-SPEC-0110.yaml). Условия и точные слова интерфейса — рабочие
уточнения агента. Все значения сохраняют область, время, доступ и покрытие.

| Сигнал сводки | Единица сигнала | Что открывает |
| --- | --- | --- |
| Open PR / draft PR | Различные открытые PR; draft — их подмножество. | PR той же области с выбранным open и, для draft, draft условием. |
| Open Issues | Различные открытые Issue. | Issues той же области с условием open. |
| Failed CI | Различные open PR хотя бы с одной подходящей записью категории failure; число Repository — отдельная величина. | PR с тем же условием, а не отдельные проверки и не Issues. Timeout не переименовывается в failed test. |
| Review requested / changes requested | Различные open PR с соответствующим независимо установленным review условием. | PR с именно этим условием; отсутствие открытых threads само по себе его не отменяет. |
| Unresolved review threads | Threads и затронутые open PR — два разных счётчика. | Различные PR, содержащие подходящий thread; пять threads могут вести к двум карточкам. |
| Blocked Issues | Различные open Issues с подтверждённым открытым direct blocker. | Эти Issues; PR и сам blocker не становятся результатами только потому, что участвуют в связи. |
| Merged PR / closed Issues за период | События либо различные затронутые объекты — единица указывается отдельно. | Различные PR или Issues с тем же событием и периодом; event count может отличаться от количества карточек. |

Внутри одного filter facet выбранные категории объединяются; разные активные
facets пересекаются. PR-only условие исключает Issue по типу области, а не
приписывает ему «здоровый CI»; симметрично для Issue-only blocker. Неизвестное
применимое состояние остаётся неизвестным. Исторический сигнал сохраняет свой
период и не подменяется динамическим Today. Переход и последующее изменение
фильтра сохраняют исходный контекст сигнала отдельно от текущей выборки.

Опциональная выборка checks-and-review-passed не включена в этот каталог как
готовый предикат: её условия по-прежнему не выбраны и её нельзя выдавать за
merge readiness. Наличие этой таблицы не доказывает, что GitHub предоставил все
нужные данные или что UI и переходы реализованы.
