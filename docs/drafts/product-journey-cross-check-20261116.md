# GitView: сверка пользовательских маршрутов

Снимок графа `ec6e374`. Это авторская выборочная сверка продуктовых сценариев, не независимое ревью всего графа и не подтверждение готовности к реализации. Сценарии в узле [0020](../../specs/nodes/GITVIEW-SPEC-0020.yaml) прошли отдельное независимое смысловое ревью; приложение, GitHub и устройство при этой сверке не запускались.

| Маршрут | Что человек может понять и сделать | Опорные узлы | Что остаётся открытым |
| --- | --- | --- | --- |
| Первый запуск → Project | При подтверждённо пустой локальной коллекции начать подключение GitHub, выбрать доступный Repository и открыть успешно сохранённый Project. Частичный поиск, неудача и неопределённый результат сохранения не изображаются как пустой GitHub или успешное создание. | [0019](../../specs/nodes/GITVIEW-SPEC-0019.yaml), [0022](../../specs/nodes/GITVIEW-SPEC-0022.yaml), [0045](../../specs/nodes/GITVIEW-SPEC-0045.yaml), [0059](../../specs/nodes/GITVIEW-SPEC-0059.yaml) | Способ авторизации, exact setup controls, многовыбор и механизм default association. |
| Project → работа → возврат | У Project с одним Repository нет обязательного повторного экрана Repository. Для нескольких доступны участники и прямой переход по поддержанному сигналу. Возврат сохраняет действительный контекст, а открытый preview не подменяется при перестройке сетки. | [0024](../../specs/nodes/GITVIEW-SPEC-0024.yaml), [0031](../../specs/nodes/GITVIEW-SPEC-0031.yaml), [0074](../../specs/nodes/GITVIEW-SPEC-0074.yaml), [0091](../../specs/nodes/GITVIEW-SPEC-0091.yaml) | Обычный первоначальный вход в многорепозиторный Project и exact native transition. |
| Today → фильтр → объект | Применимая незавершённая работа и завершённая сегодня остаются в одной сетке без исключающего фильтра. PR остаётся одной карточкой; выбранный фильтр сохраняется и не меняет GitHub. Неизвестный результат фильтра и неполное покрытие остаются различимыми. | [0027](../../specs/nodes/GITVIEW-SPEC-0027.yaml), [0042](../../specs/nodes/GITVIEW-SPEC-0042.yaml), [0089](../../specs/nodes/GITVIEW-SPEC-0089.yaml), [0101](../../specs/nodes/GITVIEW-SPEC-0101.yaml), [0102](../../specs/nodes/GITVIEW-SPEC-0102.yaml) | Дополнительные условия включения в Today, поведение при смене часового пояса и native presentation неопределённости. |
| Сигнал → соответствующая работа | Сигнал сохраняет condition, scope и applicable period; количество тредов не становится числом PR. Исторический счётчик merged может на время перехода переопределить конфликтующее исключение, не меняя сохранённую настройку. | [0047](../../specs/nodes/GITVIEW-SPEC-0047.yaml), [0056](../../specs/nodes/GITVIEW-SPEC-0056.yaml), [0062](../../specs/nodes/GITVIEW-SPEC-0062.yaml), [0092](../../specs/nodes/GITVIEW-SPEC-0092.yaml) | Значение «готово», определение долгого обсуждения и правила остальных конфликтов фильтров. |
| Сохранённое → ошибка или отзыв доступа | Ошибка обновления сохраняет доступные прошлые данные и показывает подтверждённую причину и время последнего успешного обновления, когда они известны. После подтверждённого отзыва доступа к private Repository сохранённые данные видны как last known с отметкой; синхронизация затронутого Repository останавливается, доступны восстановление или явное локальное удаление. | [0019](../../specs/nodes/GITVIEW-SPEC-0019.yaml), [0023](../../specs/nodes/GITVIEW-SPEC-0023.yaml), [0048](../../specs/nodes/GITVIEW-SPEC-0048.yaml) | Точная source evidence отзыва, recovery и политика других состояний аккаунта. |
| Объект → GitHub или sharing | Доступный путь к источнику связан с нужным объектом; отсутствие подтверждённой ссылки не заменяется выдуманным URL. Локальный просмотр, source handoff и sharing — разные действия; handoff не доказывает доставку или доступ получателя. | [0033](../../specs/nodes/GITVIEW-SPEC-0033.yaml), [0050](../../specs/nodes/GITVIEW-SPEC-0050.yaml), [0093](../../specs/nodes/GITVIEW-SPEC-0093.yaml) | Содержимое share payload и допустимость внешней передачи в разных условиях. |

Граф использует существующие понятия `Project`, `Repository`, `PullRequest` и `Issue` из выбранного **draft** ontology context; навигационный маршрут, фильтр и preview здесь не вводятся как новые предметные сущности. Структурная проверка не утверждает онтологию и не доказывает доступность данных источника.

## Граница этой сверки

В [историческом черновике 0108](GITVIEW-SPEC-0108.yaml) описана конкретная FSD-композиция, batch setup и default association. Это условный архитектурный кандидат, а не обязательный пользовательский маршрут. Для описанных выше результатов пока достаточно существующих продуктовых узлов; добавлять технический узел только ради полного переноса этого черновика не требуется.
