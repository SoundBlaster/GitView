# GitView: факты для Today и фильтров

Рабочая сверка к [0110](GITVIEW-SPEC-0110.yaml) и
[0102](GITVIEW-SPEC-0102.yaml). Она определяет, что должно быть известно для
продуктового решения, и не выбирает конкретный запрос, API budget или стратегию
синхронизации. Источники ниже описывают возможности, а не доказывают полное
покрытие данных конкретного аккаунта.

| Условие | Достаточное направление свидетельства | Что не следует из одного факта |
| --- | --- | --- |
| Идентичность карточки | Подтверждённые source, Repository, тип и identity PR/Issue; номер остаётся локальным для Repository. | Одинаковые названия и номера не объединяют объекты. GitHub REST Issues может представлять PR как Issue; требуется нормализация. [GitHub Issues API](https://docs.github.com/en/rest/issues/issues) |
| Незавершённая работа | Применимое наблюдение текущего open-состояния для того же объекта и контекста. | Ранее наблюдённый open не обязательно остаётся текущим после известного изменения. |
| Создано сегодня | Достоверное время создания того же объекта в выбранном локальном полуоткрытом интервале дня. | Время получения ответа или `updatedAt` не доказывает создание. |
| Завершено сегодня | Подтверждённый подходящий close или merge event с event time в интервале дня. У PR GitHub документирует `mergedAt`; у Issue и PR есть timeline event types, включая reopening. [Pull requests](https://docs.github.com/en/graphql/reference/pulls), [Issues](https://docs.github.com/en/graphql/reference/issues) | Текущий lifecycle не является полной историей закрытий и переоткрытий. Само существование timeline API не доказывает её полноту. |
| Фильтр failed CI | Применимые check/status факты и их классификация для выбранного PR revision context. | Новое название, обновление PR или результат checks старого revision не подтверждает текущий failed CI. |
| Полнота Today для Project | Подтверждённые границы выбранных Repository, объём по каждому применимому типу и каждой из трёх альтернатив, а также факты активных фильтров. | Список только open work не доказывает отсутствие закрытых сегодня; завершение пагинации не создаёт само по себе согласованный snapshot. |

Для одного уже известного разрешённого объекта достаточно истинности любой из
альтернатив open / created today / closed-or-merged today. Если ни одна не
доказана истинной, но хотя бы одна неизвестна, этот объект остаётся uncertain,
а не исчезает как подтверждённый non-match. Это отдельный вопрос от того,
известны ли **все** объекты в выбранной области: даже полностью оценённый
видимый набор может быть неполным из-за непрочитанного Repository или страницы.

GitHub документирует `ReopenedEvent` и другие timeline types, но точные
семантика отдельных полей после повторного закрытия, доступность событий,
пагинация и права для выбранного способа чтения должны быть проверены отдельно.
Нельзя использовать отсутствие доказательства как доказанное отсутствие
события или считать, что одна выбранная операция обеспечивает весь Today.
