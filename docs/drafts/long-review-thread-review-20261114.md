# Длительные review threads: границы смысла

В согласованной идее есть внимание к долгим тредам, но обычный счётчик
незакрытых тредов в 0062 и 0057 не отвечает на вопрос о времени. В 0094
предложена модель возраста с момента создания треда как одного возможного
признака, без заявлений о непрерывной длительности незакрытого состояния,
бездействии или том, кто должен ответить. Возраст и текущее состояние требуют
собственных подтверждений. Первая версия по-прежнему не требует показа
содержимого отдельных тредов.

Правило «долгий», порог и доступность нужного времени в GitHub ещё не
установлены. Поэтому 0094 не обещает работающий счётчик, и отсутствие значения
не означает отсутствие долгих тредов. Отдельно остаётся невыбранным правило
«проверки и review пройдены»; статус merged и причина закрытия Issue, CI,
review и треды имеют свои значения и не превращаются в merge readiness.

Сценарии 0094 и 0043 — ожидаемое поведение, а не проведённые проверки GitHub
или приложения. Уточнение является pre-canonical предложением агента.

## Рабочая интерпретация после проверки schema

Позднее 0094 предложил более узкий проверяемый proxy: открытый PR,
наблюдаемый unresolved thread и хотя бы один подтверждённый submitted comment,
созданный не менее 24 часов до reference instant. Это **возраст комментария**,
а не время создания треда, непрерывного ожидания или отсутствия активности.
Точная граница включена; 24 часа — выбранный агентом рабочий default, не отдельное
решение пользователя. При неполном списке один подходящий comment подтверждает
положительный пример, но отсутствие такого comment не доказывает отрицание.
Clock сам по себе не подтверждает, что старое состояние unresolved сохраняется.

GitHub документирует `createdAt` у [PullRequestReviewComment](https://docs.github.com/en/graphql/reference/pulls#pullrequestreviewcomment),
но не у самого thread в проверенном перечне полей. Доступ к этим данным,
их полнота, UX и полезность выбранного порога не проверены. Исторический текст
выше относится к этапу до предложения этого proxy; текущие 0094 и 0097
фиксируют новую рабочую интерпретацию.
