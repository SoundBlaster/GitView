## Управление Project

Авторская сверка acceptance, открытых вопросов и перечней сценариев 0005,
0025, 0052, 0072–0073, 0083, 0091, 0104 и 0111 с выборочным чтением
сценариев. Один Repository может оставаться в нескольких Projects; изменение
одного Project не изменяет другие или GitHub. Сохранённый Project не должен
становиться пустым, а неподтверждённое сохранение или конфликт не выдаются
за завершённое изменение. При смене состава Project-wide обзор и явно
выбранный Repository остаются разными пользовательскими намерениями.

В 0052, 0083 и 0111 уточнено, что правила persistent default association
относятся к предложенному механизму; согласованное правило «по умолчанию
один Project на Repository» от него не зависит. UI конфликтов, порядок
Projects, восстановление и выполнение контрактов хранения не проверялись.
