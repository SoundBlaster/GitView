# Источник и sharing: граница передачи

[0121](GITVIEW-SPEC-0121.yaml) уточняет [0033](GITVIEW-SPEC-0033.yaml) как
авторский кандидат для Open on GitHub и link-only sharing. Выбранный source
object, его Repository identity и подтверждённая связь с URL остаются
отдельными от имени и текущего адреса. Ссылка с неподтверждённым текущим
назначением может быть предложена как last known при допустимом доступе; адрес,
про который достоверно известно, что он ведёт к другому объекту, не выдаётся
за исходный.

| Ситуация | Предлагаемое поведение |
| --- | --- |
| Локальный отказ доступа установлен до передачи payload | Упорядочить отказ и допуск к передаче; не отдавать ограниченную ссылку, не подменять объект. |
| Ссылка уже передана системе до отказа | Ограничить последующие контролируемые приложением действия, не обещая отозвать ранее переданное. Выбор получателя ещё может не состояться. |
| Система позднее вызывает provider, которым управляет GitView | Для каждого фактического предоставления повторно проверить применимое состояние; не считать видимость share sheet подтверждением доставки. |
| Адрес использован другим Repository до передачи | Старый URL не предлагать как ссылку на исходный объект; новый адрес требует отдельного evidence той же identity. |
| Аккаунт сменился, callback старой попытки пришёл позже | Старый access не становится доступом нового аккаунта; Project и membership не удаляются из-за смены identity. |

Приложение может упорядочивать только известные ему локальные события и границу,
которой оно действительно управляет. Фактический iOS API ещё предстоит выбрать
и проверить: неизвестно, на каком именно шаге конкретная интеграция отдаст ссылку
системе и какие callbacks останутся под контролем приложения. Поэтому ни отзыв
переданных данных, ни загрузка GitHub страницы, ни доступ получателя не заявлены.
Неизвестное удалённое изменение permissions не становится локально известным
только потому, что оно произошло.
