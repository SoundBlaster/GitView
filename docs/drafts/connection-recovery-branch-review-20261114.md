# Ветка подключения: expiry и восстановление

Рабочий срез графа, не semantic approval и не доказательство работы
приложения. Проход сверху вниз: 0001 → 0019 → 0058 → 0085; взаимодействия с
0022, 0036–0037, 0044, 0048 и 0059 рассмотрены по содержанию их контрактов.

| Обязательство родителя | Уточняющий контракт | Граница готовности |
| --- | --- | --- |
| Один источник, read-only, защищённый credential и восстановление | 0019 и 0058; 0085 отделяет последнюю identity от credential usability | Способ авторизации, формат и сохранение credential не выбраны. |
| При network failure сохранить разрешённые ранее данные и показать ошибку | 0036, 0044 и 0085 сохраняют observation time и применяют текущий access | Устройство и поведение secure store не проверены. |
| При explicit denial ограничить private cache и не удалять Projects | 0036, 0037 и 0085; старый ответ не снимает ограничение сам по себе | Классификация конкретных GitHub ошибок и access evidence не выбрана. |
| Повторное подключение не раскрывает данные чужой identity | 0058, 0059 и 0085 различают подтверждённую identity и доступ к каждому Repository | Внешняя проверка identity и scoped grant ещё не установлены. |
| Первоначальная настройка и частичный discovery | 0022, 0059 и 0085 не превращают expiry или отсутствие данных в пустой аккаунт | Точное native представление и восстановление незавершённой операции остаются открытыми. |
| Видимые и доступные действия и источник свежести | 0048, 0085, 0032 и 0079 требуют видимый scoped outcome и accessible путь | Background delivery и VoiceOver требуют отдельных native проверок. |

Кандидат 0085 выбирает безопасное для последовательности разграничение:
локально подтверждённый expiry без доказанного denial не является доказательством
отзыва source access; существующая политика разрешает ранее доступный cache с
ограничениями. Если позже подтверждён explicit denial, действует ограничение
0036. Ни одна из этих формулировок не утверждает, что GitHub предоставляет
конкретное поле expiry или что конкретный HTTP status сам доказывает причину.

Ветка остаётся не готовой к реализации: ещё нужны выбранный совместимый
authorization flow, сопоставление errors и безопасная замена credential,
а также точные подтверждения реального source и платформы. Детали UI,
не меняющие контракт, могут уточняться позже; ни одна структурная проверка не
подменяет эти обязательства.
