# GitHub → Today: карта входов и ограничений

Авторская сверка действующих кандидатов [0101](GITVIEW-SPEC-0101.yaml),
[0102](GITVIEW-SPEC-0102.yaml), [0110](GITVIEW-SPEC-0110.yaml),
[0115](GITVIEW-SPEC-0115.yaml) и [0116](GITVIEW-SPEC-0116.yaml). Она делает
стыки маршрута проверяемыми; это не новый контракт, не готовый GraphQL query
и не свидетельство работы с конкретным аккаунтом GitHub.

| Вход Today | Кандидат источника и передаваемое значение | Граница доказанности |
| --- | --- | --- |
| Объект и его Repository | Typed `Issue` или `PullRequest` из Repository connection: source instance, подтверждённый Repository, typed Node ID, контекст наблюдения и доступа. Номер и название — дополнительные доступные признаки. | Адрес и локальный номер не доказывают identity; невозможно формировать карточку подтверждённого объекта при неразрешённом типе или Repository. |
| Open | Применимое наблюдение `state` того же typed объекта; отдельно для Issue и PR. Открытая выборка не ограничивается недавним обновлением. | Состояние имеет собственное время; устаревшее или недоступное значение не становится текущим open либо false. |
| Created today | `createdAt` того же объекта сравнивается с захваченным полуоткрытым интервалом местного дня. | `updatedAt`, время запроса и время сохранения не подменяют создание. Созданный сегодня объект может подходить независимо от текущего lifecycle. |
| Closed или merged today | Для PR — применимое ненулевое `mergedAt`; для закрытия — независимо связанное с объектом допустимое событие `ClosedEvent` и его `createdAt` из соответствующего `timelineItems`. | Отсутствие события в неполной timeline не означает, что события не было; текущее состояние не является полной историей повторных закрытий. |
| Население Today | Для каждого Repository и типа отдельно учитываются цели open discovery и recent discovery: `issues` и `pullRequests`, их фактические аргументы, страницы, ошибки, продолжения и контекст. | Наблюдённый объект может быть достаточен для карточки, но терминальная страница или успешный HTTP ответ не доказывает полную выборку на один момент времени. |
| Фильтры и отображение | Передаются только отдельно поддержанные и разрешённые факты; применимость CI учитывает revision. Состояния полей и ограничения сохраняются отдельно от source attempt и retention outcome. | Успешный title не обновляет CI; неизвестный predicate не превращается в false или zero. Ограниченный доступ проверяется перед отображением. |

Для Issue recent discovery кандидат применяет `IssueFilters.since`; для PR
используется отдельная connection и поддерживаемая сортировка по обновлению.
GitHub документирует `since` как фильтр по обновлению, а не по времени
закрытия; применимость и полнота выбранного способа обнаружения событий остаются
открытыми. Аргументы timeline, пагинация и права тоже не устанавливают сами
по себе полную историю. См. официальные схемы [Repository](https://docs.github.com/en/graphql/reference/repos),
[Issue](https://docs.github.com/en/graphql/reference/issues) и
[PullRequest](https://docs.github.com/en/graphql/reference/pulls).

Перед объявлением adapter готовым необходимо выбрать и проверить форму запросов,
сопоставление Repository identity при rename/transfer, права и трактовку
GraphQL errors/null propagation для фактического ответа. Нужны также независимые
проверки применимости фактов, identity и ограниченного покрытия на controlled
fixtures; доступность и поведение реального аккаунта требуют отдельного
авторизованного integration evidence. Количество страниц, частота запросов и
численный API budget намеренно не зафиксированы. Недоступность сильной гарантии
полноты не мешает показывать разрешённые подтверждённые объекты с ограничением.
