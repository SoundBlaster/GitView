# Проверка готовности листа 0049: граница Today

Состояние: **не установлена готовность к реализации**. Это ручная проверка
автора, не independent review и не canonical acceptance. Узел
[0049](GITVIEW-SPEC-0049.yaml) — структурный leaf в снимке на 14 ноября;
отсутствие детей не является достаточным условием реализации.

## Что определено

- Scope: поведение динамического Today при смене локального дня и time zone,
  включая активный PR/Issue preview и возврат к выборке.
- Ожидаемое поведение: локальные границы пересчитываются без изменения source
  timestamps; Project и явные фильтры сохраняются; открытый объект не
  подменяется; новый день с неизвестным покрытием не объявляется пустым.
- Происхождение: желание сохранять незавершённую работу и результаты дня
  исходит из обсуждения владельца; календарный расчёт и его interaction rules —
  предложения агента в 0007, 0027 и 0049.
- Проверяемые примеры: midnight, preview at boundary, new day unobserved,
  time-zone change. Они записаны как ожидаемые результаты, не запускались.

## Зависимости и блокеры

| Контекст | Что требуется для реализации 0049 | Нынешнее состояние |
| --- | --- | --- |
| 0007 / 0027 | Определение Today, состояния объекта и результата фильтра. | Предложены local day и трёхзначная логика; source field semantics и history coverage открыты. Конечная модель 0027 проверяет логические свойства, а не календарные вычисления или данные GitHub. |
| 0024 / 0042 | Сохранение scope и фильтра, identity, порядок и fallback позиции. | Предложены deterministic order и fallback; native lifecycle, источник timestamp и представление неопределённых объектов требуют проверки. |
| 0031 / 0050 | Preview сохраняет identity при обновлении и не теряет правила доступа. | Контракт записан; точное содержимое и gesture/focus behavior не проверены на iOS. |
| 0044 / 0026 / 0037 | Достаточность покрытия нового дня, timestamp и порядок конфликтующих обновлений. | Разделены полные и частичные наблюдения; критерии достаточного source coverage и reconciliation ещё не определены. |
| iOS platform | Смена локальной даты/time zone и доступность во время активного жеста. | Нет target-version решения, native implementation или device evidence; продолжительность календарных суток не предполагается постоянной. |

Лист не должен блокироваться лишь из-за невыбранного названия control, но
неопределённость достаточного coverage и native accessibility при активном
взаимодействии может менять наблюдаемый результат. До разрешения этих вопросов и готовности
предков называть его реализуемым было бы преждевременно.

## Проверки и следующий проход

Для отдельных candidate узлов SpecGraph проверил структуру и domain vocabulary
в изолированных копиях; это не проверка дат, platform behavior или сценариев.
Ручная трассировка выше не устанавливает всех transitive dependencies.
В 0049 предложено пересчитывать Today на границе, но отложить мешающую
перестановку сетки до конца активного жеста; native accessibility этого решения
не проверена. Уточнено, что полный охват Today включает и старую открытую
работу, и события выбранного дня; только созданные сегодня объекты недостаточны.
Следующий шаг — определить, какое source-specific evidence подтверждает эти
scope, не выбирая заранее GitHub API limits; затем повторно оценить родителей
и зависимости и только после этого readiness.

## Уточнение границы покрытия

Для проверки полноты нового Today теперь предложено учитывать текущий состав
Project, выбранные категории, границы локального дня и активные фильтры.
Добавление Repository с неизвестным покрытием делает расширенный scope
неполным; прежнее полное наблюдение остаётся привязанным к предыдущему составу.
Аналогичный контракт для агрегатов внесён в 0029 и 0046. Полностью покрытые
данные с разными временами наблюдения не становятся автоматически единым
моментальным снимком.

Это условия, которым должно отвечать source-specific evidence, а не доказательство
того, что GitHub действительно предоставляет такой охват. Примеры с изменением
membership и фильтра являются сценариями спецификации, а не выполненными тестами.

| Доступное свидетельство | Что можно утверждать о Today |
| --- | --- |
| Полное покрытие A; новый член B не наблюдался | По A доступно прежнее наблюдение; полный результат A+B неизвестен. |
| Для A и B есть полное покрытие требуемых условий, но в разные моменты | Можно сообщить охват и времена обоих источников; единый моментальный snapshot не доказан. |
| Покрыты созданные сегодня объекты, но не старые открытые | Полнота Today не доказана даже при нулевом числе загруженных карточек. |
| Все состояния явно исключены фильтром | Результат фильтра намеренно пуст; это не подтверждает отсутствие данных в источнике. |
| Объект подходит по известным условиям, CI для активного CI-фильтра неизвестен | Он остаётся неопределённым кандидатом, а не подтверждённым совпадением или исключением. |

Таблица — ручные примеры ожидаемой интерпретации, не исчерпывающая модель
всех комбинаций и не подтверждение реального источника.

### Today и фиксированный PR cohort

0055 предлагает отдельную аналитическую выборку, но она не меняет динамический
Today: новый подходящий PR остаётся в сетке даже после capture, фильтры Today не
переписывают сохранённый состав cohort, а смена локального дня не заменяет его
состав автоматически. Неполный исходный capture остаётся неполным в обеих
интерпретациях. Это граница кандидата; механизм capture и включение в первую
версию ещё не установлены.

При постраничном получении Today достижение последней страницы не доказывает
полного scope, если список мог измениться между страницами и source guarantees
не установлены. [Пример модели](evidence/pagination-coverage-example.py)
показывает пропуск элемента в искусственном mutable offset list; это не
утверждение о конкретном GitHub endpoint или его пагинации.

В 0027 и 0042 уточнено, что совпадение по старому CI относится к контексту
этого наблюдения: обновлённое название не превращает его в подтверждённое
совпадение сейчас. Объединение источниковых фактов с разным временем также
не доказывает, что они одновременно существовали в едином snapshot.
