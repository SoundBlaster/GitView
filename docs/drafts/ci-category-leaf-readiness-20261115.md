# CI: граница классификации и готовность ветви

Авторский разбор [0028](GITVIEW-SPEC-0028.yaml) → [0060](GITVIEW-SPEC-0060.yaml) → [0061](GITVIEW-SPEC-0061.yaml). Это не независимое review и не готовность всей ветви к реализации.

| Обязательство | Текущее состояние |
| --- | --- |
| Единица и область | CheckRun и StatusContext различаются; 0060 требует идентичность, актуальную revision и выбор попыток. Реальный выбор применимых PR checks пока не установлен. |
| Вход классификации | 0061 задаёт одну установленную применимую запись с family и контекстом наличия или ошибки полей; отсутствие или ошибка поля не становится null. |
| Результат | Один из success, failure, pending, special, unclassified с исходным смыслом. Классификация не делает сеть, выбор попыток или merge decision. |
| Счётчики и unknown | 0061 считает категории по совместимому набору; 0028 и 0044 сохраняют отдельную полноту. Наблюдённый failure при partial data возможен; отсутствие failure по partial data не доказывается. |
| Проверка | В 0061 записаны ожидаемые сценарии, включая возвращённый null и ошибку поля; это не выполненные тесты. Потребуются TDD тесты классификации и отдельно source, permission, revision, pagination и native evidence. |

Источник nullable `conclusion` и обязательного `status` — [GitHub GraphQL CheckRun](https://docs.github.com/en/graphql/reference/checks#checkrun). Поведение отсутствующего или error-affected поля — правило GitView, а не гарантия источника о допустимых сочетаниях.

Для полного implementation-ready листа ещё требуется проверить Swift/SpecificationCore границу, согласовать представление evidence и applicability с потребителем и проверить исходные состояния при реальном доступе. Правила для отдельных enum не завершают сборку CI: выбор revision и текущих попыток, permissions и coverage остаются открытыми. Код приложения и API budgets не выбирались.
