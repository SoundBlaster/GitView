# Today, история и burn down

Пользовательский пример — в течение дня видно 100 PR, из которых 95 уже влиты.
Он требует сохранять карточки и позволяет показать текущую разбивку Today;
он сам по себе не задаёт фиксированную выборку для будущих дней или доказанную
историю того, как менялось число открытых PR.

| Представление | Что измеряет | Что необходимо |
| --- | --- | --- |
| Разбивка Today | Текущее наблюдаемое состояние PR или Issue из динамической выборки Today. | Идентичность, актуальный состав и фильтры, сопоставимые состояния и достаточное покрытие. Новый подходящий PR может увеличить итог. |
| Результаты периода | PR с merge или Issue с событием закрытия в выбранном интервале. | Подтверждённое время события и покрытие периода; событие отделено от текущего состояния. |
| История открытой работы | Наблюдавшееся число открытых PR или Issue на конкретных временных точках. | Сохранённые или обоснованно восстановленные точки с собственным scope и coverage. Отсутствующие точки — пропуски. |
| Fixed-cohort burn down | Изменение состояний заранее зафиксированного набора PR. | Явные состав и момент capture, идентичность, состояния и данные для каждой точки. Новые PR не добавляются в cohort молча. |

В кандидате 0057 описана динамическая разбивка; 0055 остаётся предложением
fixed cohort, а 0069 — предложением начальных исторических рядов. Выбор cohort
для первой версии и данные, необходимые для исторической кривой, остаются
открытыми. Если есть только текущий срез, GitView может показать только его;
он не доказывает предыдущие точки или число merge-событий в течение дня.

Пример 100 → 101 PR и другие сценарии — спецификационные ожидания. История,
GitHub coverage, хранение и графики не реализованы и не проверены.
