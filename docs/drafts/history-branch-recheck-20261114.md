# Повторная сверка ветви истории GitView

Авторский обзор после уточнения временных контекстов, навигации и очистки.
Это не независимое принятие и не утверждение готовности к реализации. Все
перечисленные спецификации остаются `idea / pre_canonical`; версии ниже
фиксируют границы этого обзора.

## Проверенные решения

- Сохранённая точка отражает своё время, единицу, предикат, Repository scope,
  membership basis и уровень coverage. Отдельные поздние события не превращают
  старый полный aggregate в новый точный total. Пробел не выглядит наблюдённой
  непрерывной линией; период и ограничения доступны также без цвета и drag.
- Исторический outcome может открывать независимо подтверждённые объекты с
  тем же периодом и исходным basis. Поздняя выборка сохраняет собственное
  evidence и не выдаётся за исходный состав только из-за равенства чисел.
- Доступ и подтверждённая очистка переоцениваются при возврате к графику;
  неуспешная отдельная операция не отменяет другую успешную очистку.
- Предложенный default использует фиксированный набор текущих members как
  ретроспективный scope и не выдаёт его за фактический состав в прошлом.
  Диапазоны 7/30 дней и отсутствие истечения истории по возрасту также остаются
  решениями агента, а не отдельно подтверждённым выбором владельца.

## Что ещё необходимо для implementable leaves

1. Для каждого выбранного показателя определить реальные source fields, доступ,
   identity и достаточность coverage либо явный ограниченный результат. Нельзя
   обещать полную историю только по наличию event type или успешной pagination.
2. Завершить storage contracts для lineage, совместного использования current и
   historical evidence, transaction/recovery, retention budget и доступной
   диагностики. 0113 и 0117 предлагают направление, не реализованный provider.
3. Определить реализуемые контракты входов и выходов вычисления точек,
   выбора sample и очистки, включая связь с фактической версией зависимостей.
   Графовые `depends_on` и сценарии сами по себе не определяют Swift API.
4. Выбрать пользовательские controls и допустимые safe fallbacks в соответствии
   с системным интерфейсом, не закрепляя непроверенные предположения о iOS.

Отдельно после реализации потребуются source integration, restart/crash и
concurrency на реальном storage, проверка календаря и native accessibility.
Их нынешнее отсутствие не заменяет решения перечисленных выше контрактов;
прохождение candidate YAML checks не считается проверкой этих свойств.
