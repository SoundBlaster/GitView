# GitView: сквозные маршруты и готовность графа

**Дополнение после уточнения 0113–0116.** Снимок и таблица ниже сохраняют
историческую оценку 112 кандидатов. В текущем [снимке связей](evidence/autonomous-goal-setup-journey-links-20261114.json)
116 кандидатов и 52 структурных листа: отсутствующих целей и циклов не найдено.
Сборка первого запуска [0108](GITVIEW-SPEC-0108.yaml) теперь явно зависит от
решения валидности Project 0111, доступа 0112, сохранения 0113 и восстановления
связки credential 0114. Ранее 0112 ошибочно зависел от 0108, что мешало такой
композиции без цикла; направление исправлено. Путь работы 0115 отдельно включает
обмен наблюдениями 0116. Это наличие заявленных рёбер, а не исполнение сценариев.

Контракты 0113 и 0114 предлагают конкретное разграничение SQLite и Keychain,
восстановление после прерывания и независимые исходы. В 0108 добавлен сквозной
случай: Project сохранён, но после перезапуска secure slot недоступен. Нельзя
считать Project потерянным или подключение работающим; применимость offline
данных определяется 0036 и 0113–0114. Точные файловая защита, поведение
Keychain, граница незафиксированного до crash отзыва доступа и применимость
GitHub authorization остаются открытыми, как и проверка реализации на устройстве.
Две изменённые specs прошли candidate check и
[ontology advisory](evidence/autonomous-goal-ontology-check-setup-reconciled-20261114.json):
проверены форма и выбранные ссылки, не доказаны семантика и работа приложения.

Рабочая содержательная оценка по состоянию файлов на 14 ноября, не canonical
принятие. Исходные решения владельца и прототипы используются как требования;
более поздние детали, выбранные агентом, сохраняют отмеченное в кандидатах
происхождение. Ни наличие сценария, ни `checked` не доказывают готовность кода.

Снимок содержит 112 кандидатов `idea / pre_canonical`, из них 52 структурных
листа. У каждого листа есть хотя бы один явно записанный открытый вопрос; сам
этот факт не доказывает, что каждый вопрос блокирует реализацию. Отдельный
узел приёмки [0043](GITVIEW-SPEC-0043.yaml) содержит 76 описанных сценариев и
является сквозной приёмкой, а не самостоятельной единицей реализации только
потому, что у него нет потомков по `refines`.

не выявил diagnostics, но semantic approval и compiler provenance не подтверждены.

## Результат оценки

Граф достаточно развит для предметного обсуждения и содержит сквозные
примеры сложных состояний. Считать его полностью пригодным к реализации пока
нельзя: общие архитектурные зависимости, source-specific свидетельства,
границы сохранения и нативные контракты ещё содержат существенные пробелы.
Количество сценариев не является оценкой качества; для каждого будущего
implementation leaf потребуется отдельная содержательная проверка входов,
выходов, инвариантов, отказов и применимых зависимостей.

Следующий приоритет — начало пользовательского пути: связать контракт выбора
GitHub Repository с достаточно конкретной границей сохранения Project и
прояснить исходы подтверждённой записи, конфликта и неизвестного результата.
Это не разрешение на реализацию и не требует заранее выбирать API budgets.
