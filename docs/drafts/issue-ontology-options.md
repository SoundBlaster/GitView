# Issue: заготовка для выбора

Статус: предложение агента для обсуждения по запросу пользователя
«Давай issue разберем» (`conversation:gitview/excerpt-36`). Все галочки пустые;
пункты ещё не выбраны. Это не изменение ontology package и не готовые требования
приложения. Можно выбирать блоки целиком или отдельные номера, как для PR.

Кандидатное значение: зафиксированный вопрос, проблема или запрос на работу.
Эта формулировка предлагается отдельно от состава свойств и тоже требует
обсуждения. Issue может выступать мотивом в обсуждённой цепочке действий актора;
это не означает, что каждая Issue породила изменение кода или PR.

## A. Идентификация и описание

- [ ] A1. Идентификатор в источнике и номер Issue в контексте репозитория.
- [ ] A2. Название.
- [ ] A3. Описание / текст.
- [ ] A4. Ссылка на первоисточник.

## B. Состояние и характеристики

- [ ] B1. Открыта / закрыта.
- [ ] B2. Причина состояния или закрытия, если предоставлена GitHub.
- [ ] B3. Метки / labels.
- [ ] B4. Тип Issue, если задан в источнике.

Закрытие не следует автоматически понимать как выполненную работу. Тип и
labels — разные характеристики. «В работе», «готово» и «требует внимания» не
добавляются как исходные состояния Issue. Статусы из GitHub Projects требуют
отдельного контекста; GitHub Project не тождественен Project в GitView.

## C. Контекст и участники

- [ ] C1. GitHubRepository, которому принадлежит Issue.
- [ ] C2. Автор / создатель как роль участника.
- [ ] C3. Назначенные исполнители / assignees.

Назначение исполнителя не доказывает, что работа началась. Автор и assignee не
автоматически являются User приложения, coding agent или актором конкретного
изменения. Выбор роли не вводит новую ontology entity автоматически.

## D. Связи

- [ ] D1. Связанные PR с различением явной связи на закрытие и простого упоминания,
  если эти данные доступны в источнике.
- [ ] D2. Родительская Issue и дочерние Issues / sub-issues.
- [ ] D3. Зависимости: что блокирует Issue и что блокируется ею.
- [ ] D4. Milestone, если задан.

Это кандидаты связей по источнику, а не доказанные отношения через действия
акторов в пользовательском смысле Ontology. Упоминание PR не означает закрытие
Issue, а явная связь на закрытие сама по себе не доказывает мотив конкретного
актора. Milestone здесь предлагается как ссылка на метаданные источника; новый
ontology-класс автоматически не создаётся.

## E. Обсуждение — счётчики

- [ ] E1. Число комментариев.
- [ ] E2. Число участников обсуждения.

Комментарии Issue не приравниваются к ReviewThread PR. Метрика «незакрытые
треды» сюда не переносится. Полный просмотр комментариев этим пунктом не
предлагается. Число комментариев и число участников имеют разный смысл.

## F. Дочерняя работа — счётчики

- [ ] F1. Общее число непосредственных sub-issues.
- [ ] F2. Число закрытых непосредственных sub-issues.

Это опциональное дополнение к D2: счётчики можно выбрать без просмотра списка.
Доля закрытых sub-issues не объявляется процентом выполненной работы. Закрытые
дочерние Issues могли иметь разные причины закрытия; их трудоёмкость неизвестна.
Точный источник и правила подсчёта уточняются в спецификации.

## G. Время

- [ ] G1. Время создания и последнего обновления.
- [ ] G2. Время закрытия, когда применимо.
- [ ] G3. Время получения наблюдения и его источник.
- [ ] G4. Время последнего комментария, если он есть и данные доступны.

Последнее обновление Issue не следует автоматически считать последним
комментарием. «Давно нет ответа» требует отдельного определения: кому и на что
должны ответить, каков порог ожидания. Недоступные данные не равны нулю или
отсутствию работы. Набор свойств не объявляется полным eventcore:StateSnapshot.

## Граница следующего шага

Сначала пользователь выбирает состав. Затем уточняем значения, связи, роли и
неизвестность; получение, вычисление, обновление и отображение описываем в
спецификациях GitView. CI и размер diff не приписываем самой Issue: при
необходимости их можно рассматривать через выбранные связанные PR.

Источник для сверки доступных понятий и свойств:
[GitHub GraphQL: Issues](https://docs.github.com/en/graphql/reference/issues).
Этот список — предложение для GitView, а не копия API-схемы или утверждение
доступности каждого поля для всех репозиториев. Локальные ссылки excerpt не
являются удостоверенными ID сообщений.
