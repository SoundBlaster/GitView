# Project lifecycle: сквозная сверка ветви

Исторический срез до [0083](GITVIEW-SPEC-0083.yaml): этот новый candidate
уточняет review и retry после конфликта. Он не подтверждает готовность ветви
или выбранную реализацию storage.

Срез 14 ноября: `0001 → 0005 → 0025 → 0082` по `refines`. Создание через
выбор репозиториев и восстановление default association дополнительно
описаны в соседней ветви `0022 → 0045 → 0052`, на которую 0082 ссылается
как на зависимость. Наличие связи не является подтверждением принятия или
проверки ни одной ветви.

| Обязательство | Контракт и граница |
| --- | --- |
| Project содержит один или несколько Repository; Repository может состоять в нескольких Projects | 0005/0025. Пустой сохранённый состав запрещён; это не означает удаление исходного Repository при изменении membership. |
| По умолчанию один Project на Repository | 0022/0025/0045/0052. Идемпотентность default association и её снятие при изменении состава — предложения агента, не отдельно утверждённый механизм пользователя. |
| Изменение состава, имени и удаление | 0025, 0024 и 0082. Удаление Project локальное; источник и другие Projects сохраняются. Формальный actor/action удаления membership остаётся ontology candidate. |
| Прерывание после отправки | 0025/0045/0052/0082 различают подтверждённое состояние, отсутствие commit и неизвестный исход. Нет доказательства поведения выбранного durable store. |
| Пересекающиеся правки и удаление | 0082 предлагает не перезаписывать подтверждённое изменение устаревшим состоянием и не восстанавливать удалённый Project запоздавшей правкой. Реализация и политика автоматического merge не выбраны. |
| Отображение и доступ | 0024, 0036 и 0082 требуют сохранять исходный контекст и не показывать restricted данные. Конкретный конфликтный UI, privacy boundary и native accessibility ещё не проверены. |

## Применимость 0079

1. **Domain behavior:** TDD с deterministic cases для сохранения идентичности,
   непустого состава и независимости общих Repository. Для pure policy network
   mock не требуется; сохранение и обнаружение конкуренции относятся к границе
   данных и требуют управляемого test double.
2. **Storage и recovery:** отдельно проверить выбранный реальный durable store,
   включая два stale saves, delete перед поздним save, потерянный acknowledgement,
   restart и uniqueness default association. Прежние finite models не являются
   evidence этого механизма и не покрывают все новые сценарии 0082.
3. **Source и приватность:** проверять в двойниках изменение доступа/identity,
   а для реального adapter отдельно подтвердить source mapping и permissions.
   Локальная правка Project не должна записывать изменения в GitHub.
4. **UI:** конфликт, invalid edit, неизвестный исход и подтверждённое удаление
   должны быть различимы и доступны без одного жеста или цвета. Для pure
   membership decision проверка VoiceOver не применяется; для UI восстановления
   она требуется на соответствующей платформе.

Ни один product test, реальный restart выбранного store или native accessibility
check не выполнялся. Ветка не признана реализуемой независимо от открытых правил
merge, удаления и source access. Следующий шаг — разобрать ожидаемый результат
явного разрешения конфликта двух правок, в том числе какие намерения оператора
могут быть сохранены без тихого восстановления устаревших данных.
