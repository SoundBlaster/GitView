# Открытые решения продуктового прохода

Рабочий список по состоянию после сверки маршрутов. Это не новые решения владельца и не требование решить всё до прототипа; независимое итоговое review может изменить предложенную классификацию. Предыдущий список от 15 ноября — исторический, включая отменённые предложения скрывать данные после отзыва доступа.

## Принято владельцем

- Обычный вход в multi-Repository Project открывает общую сетку; список Repository находится в настройках Project.
- Pinch дискретно меняет детализацию; при достижении максимального размера ячейки происходит переход на следующий уровень для определённого объекта. Граница зависит от ширины сетки и максимального размера в pt; точное значение и выбор неоднозначной цели открыты.
- Делиться самим локальным Project пока не требуется; sharing объектов GitHub остаётся.
- Внешний отзыв доступа GitHub и локальная смена аккаунта — разные события. Граница A → B описана ниже.
- Сигнал внутри отфильтрованной области сохраняет её контекст при переходе; на сигнал вне этой области посторонний фильтр не влияет. Подробнее — 0092.

## Показать владельцу перед утверждением продуктовой картины

| Вопрос | Уже выбрано | Что не установлено и почему это важно |
| --- | --- | --- |
| «Готово» и ожидающее review | Отдельно показываются наблюдаемые CI, review, треды и результаты; завершённые сегодня не исчезают из unfiltered Today. | Единый критерий готовности и то, кому следует ответить, не выбраны. Без них нельзя обещать единый ready-to-merge счётчик. |
| Долго ожидающий ответа тред | Пользователь хочет видеть проблемные и долго ожидающие ответа обсуждения; показываются счётчики, чтение треда в GitView не требуется. | Значение, по которому заметить ожидание, и порог не выбраны; нельзя подменить их количеством сообщений или 24 часами. |
| Иерархия фильтров | При переходе сохраняется исходный контекст сигнала; посторонний фильтр не сужает его выборку. Точные уровни, наследование, видимое представление и возврат остаются открытыми. |

## Допустимо уточнять после принятия общей картины

| Вопрос | Граница |
| --- | --- |
| Sharing | Выбраны переход к GitHub и лёгкий sharing объектов. Делиться самим локальным Project в первой версии пока не требуется; точный payload и private-data handoff остаются открытыми. |
| Фильтры | Lifecycle filters сохраняются, Today использует локальный день, переход из исторического merged counter временно снимает конфликтующий merged exclusion. Точная область настроек, reset и иные overrides открыты. |
| Доступ и смена аккаунта | При внешнем подтверждённом отзыве GitHub данные сохраняются и видимы с индикацией и известным временем, пока соответствующий аккаунт остаётся активным; sync останавливается. Пока активен B, ранее сохранённые приватные данные A не показываются и не удаляются из-за переключения. Поведение после возврата к A и другие случаи остаются открытыми. |
| Графики | Текущий состав Project — основа исторического графика; недостающая история остаётся видимой как ограничение. Минимальный полезный набор метрик и периодов для первой версии, формула формального burn-down и источник исторических данных не выбраны. |
| Будущие возможности | Календарь максимального отдаления, sliding preview и глубина внутри PR остаются будущими направлениями; first-version static long-press preview и доступные альтернативы сохранены. |

## Техническое уточнение

Авторизация и разрешения GitHub, структура запросов и лимиты, источник истории, схема локального хранилища, стратегии синхронизации и exact native controls уточняются при проектировании. Тестируемость, DI, TDD и моки сети/данных остаются прямо заданным engineering direction; они не являются доказательством работающей реализации.
