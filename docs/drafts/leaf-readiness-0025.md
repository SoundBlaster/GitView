# Проверка готовности листа 0025: Project lifecycle

Состояние: **не установлена готовность к реализации**. Это самоаудит автора,
не независимый review, не canonical acceptance и не разрешение на запуск
implementation pilot. [0025](GITVIEW-SPEC-0025.yaml) является структурным leaf
по `refines` на текущем снимке; связанным поведением setup владеет 0045.

## Что определено

- Сохранённый Project имеет локальную identity, имя и хотя бы один Repository;
  один Repository может состоять в нескольких Projects.
- Изменение или удаление одного Project не удаляет source Repository и не
  меняет другие Projects. Попытка сохранить Project без участников отклоняется.
- Предложены default association и её снятие при удалении связанного Repository;
  повторное подтверждение использует существующую association, если она есть.
- Сценарии и эти точные lifecycle rules — предложения агента на основе
  согласованного состава Project, а не отдельное утверждение владельца.

## Свидетельства и границы

| Проверка | Что получено | Чего она не доказывает |
| --- | --- | --- |
| Candidate и ontology vocabulary | 0025 прошёл structural candidate check и проверку терминов для конкретной SHA-256. | Смысловое принятие и работоспособность создания/удаления Project. |
| Конечная модель | Для двух Repositories и двух Project slots проверены 64 допустимых состояния и 418 последовательных переходов. | Конкурентность, хранилище, network access, recovery после kill и реальный UI модель не описывает; модель и spec составлены одним автором. |
| Перекрёстный сценарий | Найденное противоречие между default association и удалением её Repository исправлено в 0025 и зафиксировано в журнале. | В соседних узлах всё ещё могут быть другие несовместимые предположения. |
| 0045 / 0036 / 0038 | Описаны частичное подтверждение, сохранение неизвестного результата и отличие отказа доступа от offline. | Не определены persistence/operation evidence после завершения процесса и source evidence, достаточное для access и identity. |

## Блокирующие вопросы для readiness

1. После остановки процесса в момент сохранения нужна определённая наблюдаемая
   развязка: как распознать уже сохранённую association, как не создать вторую
   и как показать результат, если состояние самого хранилища неизвестно.
2. Механика подтверждения для выбранного Repository должна согласоваться с
   локальным кэшем и 0036/0038 без утверждений о конкретной GitHub API.
3. Default association остаётся самостоятельным авторским продуктовым
   решением. Нужно проверить его смысл, в том числе после изменения состава,
   и не спутать его с формальным онтологическим отношением.
4. В онтологии draft.5 нет отдельного `RemoveRepository` action; подготовлен
   [candidate для review](../../ontology/review/remove-repository-action-candidate.md).
   Это gap вопроса о предметном действии, а не требование создавать entity
   только ради симметрии.

[0052](GITVIEW-SPEC-0052.yaml) предлагает наблюдаемую атомарность одного
сохранения, повтор через durable association и явное unknown при недоступной
или несогласованной конфигурации. Для предложенной decision table построена
[конечная модель](evidence/default-save-recovery-model.py) и получен
[результат](evidence/autonomous-goal-default-save-model-20261114.json) для
32 сочетаний пяти входов. Позднее 0052 дополнен требованием единственности
association при пересекающихся или поздних сохранениях. Модель не подтверждает
достоверность самих входов, реальную атомарность или это конкурентное свойство. Механизм и evidence
хранилища остаются открытыми; тесты приложения и код не существуют. Следующий
шаг — проверить 0052 против соседних требований и оценить, какие гарантии
нужны от локального persistence до определения его технологии.
