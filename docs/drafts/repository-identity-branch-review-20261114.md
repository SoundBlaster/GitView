# Repository identity: сквозная сверка ветви

Срез 14 ноября: `0001 → 0002 → 0038 → 0080` по `refines`. В candidate graph
у 0002 один непосредственный уточняющий узел 0038, у 0038 — 0080, у 0080
потомков нет. Это авторская проверка ветви, а не утверждение, что исходный
product graph или ontology package завершены.

## Применимость требований 0079

- **Pure identity policy.** TDD и независимые deterministic cases применимы:
  одинаковые и разные точные IDs в одном instance, отсутствующий/неверный ID,
  неизвестный instance и несовместимые ID kinds. Network fake не обязателен для
  чистого сравнения, потому что источник не вызывается в этом тесте.
- **Обработка и сохранение наблюдений.** Нужны управляемые source/data doubles
  для reordered responses, конфликтов, 404 и отказа доступа. Отдельная проверка
  реального adapter должна установить точное декодирование; проверка выбранного
  durable store и restart — отсутствие потери точности и нарушение связей.
  Результат fake не подменяет эти evidence.
- **Source integration.** Для выбранного adapter необходимы документированные
  значения, authority источника, условия ID и ordering; живой rename/transfer
  не выполнялся. Реальный source check не должен требовать записи в репозиторий
  владельца без отдельного соответствующего полномочия.
- **User-facing путь.** Выбор и сравнение ID сами по себе не содержат жеста или
  visual UI; тест жеста для pure policy не применяется. Overview, отображение
  stale/unknown адреса, отказа доступа и source navigation требуют отдельной
  accessibility и native проверки. Нельзя сообщать VoiceOver или device pass
  по результату теста сравнения.

## Зависимости и границы вывода

Только по `depends_on` 0080 достигает 19 других узлов, 0038 — четыре, 0002 —
ни одного. Это свидетельство текущих рёбер, а не 19 независимых блокеров;
прямые и транзитивные зависимости необходимо отдельно оценить по семантике
SpecGraph. Общий testability 0040 и accessibility 0017 применяются по смыслу,
а не становятся автоматически проверенными из-за пути или его отсутствия.
Использованы собственные описания сценариев; product implementation, red/green
TDD, реальные адаптеры, UI и GitHub integration не запускались.

Вывод: в ветви стало меньше неоднозначностей, но leaf 0080 и его контекст пока
не обладают проверенной готовностью к независимой реализации. Следующий
содержательный шаг — уточнить доступный источник ordering адреса и source
identity evidence, отделив документированные гарантии от предположений.
