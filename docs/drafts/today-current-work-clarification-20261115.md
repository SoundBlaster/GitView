## Два варианта для только что влитого PR

Пусть X подтверждённо влит, identity и scope известны, доступ разрешает
отображение. Числа ниже — условный пример с достаточными основаниями для
соответствующих счётчиков; ошибка или неполное покрытие оговариваются отдельно.

| Вариант | Карточка X | Счётчик |
| --- | --- | --- |
| **Временно оставить** | X остаётся в текущем обзоре с отметкой merged по явному правилу. Состав и срок удержания ещё нужно выбрать. | Счётчик открытых PR уменьшается; если выбран отдельный счётчик текущих видимых карточек, X пока остаётся в нём. Историческая метрика merge учитывается в выбранной области и интервале при достаточном evidence. |
| **Показывать итог в метриках** | X покидает выборку текущей незавершённой работы после подтверждённого merge; это не удаление PR из GitHub. | Счётчик открытых PR и счётчик видимых карточек уменьшаются; результат отражается в метрике merge при достаточном evidence и выбранном периоде. |

Владелец одобрил **второй вариант для влитого PR**: карточка покидает текущую
незавершённую работу, а результат отражается в метрике при достаточных данных.
Решение и адресованный им текст предложения сохранены в SpecDraft revision
`a939a7dabd094fe29fa89305b56695d6`, nodes
`current-work-merge-metrics-proposal` и `current-work-merge-metrics-decision`.
Первый вариант выше сохранён как история обсуждения. Не все завершённые объекты обязательно имеют один
срок или одинаковую семантику. Неопределённое или частичное обновление не
подтверждает ни merge, ни удаление: ранее разрешённый факт и его время можно
использовать только в применимом контексте, а новые scope и coverage не
выдумываются. При изменении доступа действует 0036. Полный счётчик требует
отдельных данных о популяции, условиях, текущих значениях и допустимом
раскрытии; неполный источник не равен нулю. Подробности прежнего примера
сохранены [отдельно](today-merged-pr-partial-refresh-contract-20261115.md) как
условный исторический кандидат.
