# Проверка готовности листа 0053: конфликт наблюдений

Состояние: **готовность к реализации не установлена**. Это ручной авторский
разбор candidate [0053](GITVIEW-SPEC-0053.yaml), а не independent review,
утверждение или свидетельство работы приложения. Ветка отвечает за корректность
представления ранее полученных данных при пересекающихся обновлениях; конкретный
GitHub API, источник порядка и формат хранения не выбраны.

## Проверенные смысловые границы

| Связь | Контракт и остающаяся неопределённость |
| --- | --- |
| 0026 / 0037 → 0053 | Доказуемо старое значение не перезаписывает новое; если источник не даёт надёжного порядка, конфликт сохраняет неопределённость. Источник доказательства и правила совместимости scope ещё не определены. |
| 0044 → 0053 | Порядок завершения попыток описывает сетевые попытки, а не свежесть source facts. Частичный успешный запрос не означает разрешения конфликта или полного покрытия. Отображение истории попыток остаётся открытым. |
| 0036 → 0053 | Явный отказ ограничивает private data независимо от конфликта; поздний ответ сам не восстанавливает доступ. Признаки source denial и восстановление на уровне конкретного репозитория ещё требуют source contract. |
| 0038 → 0053 | Сравнивать можно только подтверждённую identity одного объекта. При неизвестной identity нельзя сливать факты по имени или номеру. Правила сравнимости разных запросов ещё не формализованы. |
| 0046 → 0053 | Счётчик с неопределённым входом не становится подтверждённым текущим итогом. Конкретная индикация и доказательство достаточного покрытия по каждой метрике остаются открытыми. |

При текущем предложении разрешение конфликта требует основания, которое
покрывает **всех** оставшихся конкурентов. Если часть необходимых сведений
утеряна, факт остаётся неопределённым; успешное завершение ещё одного запроса
само по себе не восстанавливает доказательство. При этом спецификация не
предписывает сохранять private values или конкретную структуру записей.

## Минимальные контрпримеры для последующей приёмки

1. Запрос B завершился ошибкой, пока A выполнялся; A затем вернул partial
   success. Порядок попыток известен, но это не доказывает полноту или порядок
   значений из источника. До завершения A ошибка B не исчезает из состояния.
2. Значение C подтверждённо новее A, но его отношение к конфликтующему B
   неизвестно. Нельзя объявить конфликт A/B разрешённым только на основании C.
3. После отказа в доступе приходит ранее начатый ответ с private данными.
   Он не должен раскрыть данные или снять отказ. Независимый разрешённый scope
   остаётся доступным, но не делает недоступный scope пустым.
4. Совпадают номера PR в разных репозиториях. Это разные факты; их не следует
   сопоставлять как конфликт одной identity.

Это заданные сценарии, **не выполненные тесты**. Прежде чем считать лист
реализуемым, нужно определить доступные source evidence и совместимость scope,
recovery при их утрате, наблюдаемые исходы при неопределённости и проверить
согласованность предков. Получение точных API limits для этого документа не
требуется; оно не заменяет эти контракты.

## Поля и применимость source evidence

0044 различает отсутствующее в ответе поле, null-like значение с ошибкой и
подтверждённое источником пустое значение. 0053 не распространяет revision
PR на review, comments и другие факты без основания, что эта revision их
упорядочивает. Позже полученный title не обновляет время старого review.
Это условия к source contract, а не утверждение о поведении конкретного API.
