# Проверка готовности ветви 0022: запуск и настройка Projects

0022 — родительский узел с уточнениями 0045 и 0052, а не структурный leaf.
**Готовность ветви к реализации не установлена.** Это авторский разбор,
сценарии которого не исполнялись на приложении или iOS.

| Состояние | Предлагаемое поведение | Где остаётся неопределённость |
| --- | --- | --- |
| Успешно прочитанная локальная коллекция пуста | Показать путь подключения и выбора репозиториев; не утверждать, что GitHub пуст. | Точная последовательность и вид setup. |
| Локальная конфигурация не читается | Показать локальную проблему и путь восстановления; не выдавать её за первый запуск и не сбрасывать данные. | Детали storage recovery и способ безопасного устранения повреждений. |
| Данные локального Project сохранены, GitHub временно offline | Показать разрешённые ранее сохранённые данные с временем и ошибкой. | Политика свежести и точное представление. |
| Доступ к private source явно запрещён или источник отключён | Сохранённый Project остаётся в конфигурации; ограниченные детали скрываются согласно 0036. | Надёжные source signals и правила восстановления доступа. |
| После подтверждения части выбора приложение завершилось | Сохранённые Projects доступны после успешного чтения; остальные исходы не объявляются сохранёнными или неуспешными без свидетельства. | Долговечность контекста batch и восстановление неизвестного in-flight outcome. |

Контракт 0052 предлагает атомарную видимость Project и default association и
уникальность при конкурентных сохранениях. Его конечная модель проверяет
абстракцию, а не реальную storage transaction. 0045 разрешает retry отдельных
выборов, но не доказывает, что список незавершённых выборов переживёт
завершение процесса: если такого контекста нет, приложение не должно делать
вид, будто точно знает исход каждой незаписанной операции. 0024 отдельно
предлагает открывать обзор при cold launch, а не восстанавливать старый private
route; это агентское решение, не отдельно утверждённый пользователем выбор.

До readiness нужны конкретный контракт хранения и восстановления batch context,
source identity/access evidence, безопасное поведение при повреждении
конфигурации, доступные состояния setup и проверка согласованности родителей и
системного lifecycle. Эти вопросы не требуют сейчас фиксировать лимиты GitHub.

### Уточнение предложенного контракта batch

Последующее уточнение 0045 предлагает надёжно сохранять подтверждённый состав
выбора до запуска его Project mutations, а также отмену и сведения, необходимые
для сопоставления каждого результата после перезапуска. Ранее отмеченное
отсутствие контракта тем самым закрыто **как предложение**, но его реализация,
атомарность, устойчивость к повреждению и проверка cancellation/submission race
не доказаны. Если operation record недоступен, исчерпывающий список результатов
не заявляется; source-derived private данные показываются с учётом 0036.
