# GitView: готовность пилотной спецификации

Статус: **пилотный набор требований готов для планирования реализации**.
Это оценка полноты содержательного первого среза, а не свидетельство
существования приложения, завершения тестирования или готовности к выпуску.
Основа — согласованные решения беседы и поручение самостоятельно закончить
пилотную спецификацию (`conversation:gitview/excerpt-72`).

[Граф спецификаций](drafts/specification-graph.md) содержит корень и связанные
узлы с ожидаемыми результатами и границами. [Сквозная приёмка](drafts/GITVIEW-SPEC-0020.yaml)
собирает пользовательский путь; конкретные правила находятся в узлах ниже.

## Первый пилот

1. Подключить один GitHub account, выбрать доступные repositories и организовать
   их в Projects. По умолчанию один Project соответствует одному Repository;
   один Repository может участвовать в нескольких Projects.
2. Открыть Project, увидеть PR и Issue, незавершённую работу и сегодняшние
   результаты. Не скрывать merged/closed по умолчанию; разрешить явные фильтры.
3. Менять плотность сетки, открыть Peek and Pop и перейти к обзору выбранного
   объекта, его первоисточнику или системному sharing ссылки.
4. Показывать отдельные сигналы CI, review и threads, сводки и графики, когда
   данные позволяют. Для общих итогов не повторять общие repositories.
5. Открывать сохранённые наблюдения, обновлять их по запросу и при возможности
   iOS, показывать ошибку, время и неполный охват. Отличать отсутствие данных
   от подтверждённого пустого результата и явный отказ в доступе от offline.
6. Предоставлять доступные альтернативы жестам и следовать системному iOS
   дизайну; использовать FSD iOS и SpecificationCore по их предметным ролям.

## Рабочие решения для пилота

- `Today` использует локальный календарный день устройства; открытые PR и
  Issue входят как незавершённые, включая созданные ранее.
- Одного GitHub account достаточно для первого среза. При явном отказе в
  доступе или локальном disconnect приватный кэш блокируется от просмотра и
  сохраняется до явной очистки; временная сетевая ошибка сама по себе не
  блокирует ранее разрешённые данные.
- По умолчанию sharing передаёт source link, не содержимое приватного объекта.
  Получатель получает доступ только в пределах собственных GitHub permissions.
- Сигналы CI, review и незакрытых threads независимы. Ни один из них в
  одиночку не доказывает возможность merge.

Это самостоятельные уточнения агента в рамках порученного пилота; они не
приписываются дословно пользователю. В случае изменения решения должны
обновляться связанные узлы и сценарии.

## Позже и на этапе реализации

Скользящий preview, календарный масштаб, погружение внутрь PR, дополнительные
провайдеры и account, а также write actions GitHub отложены. Пока не выбраны
конкретные OAuth flow и scopes, REST/GraphQL queries, устройство базы,
частоты обновления, iOS deployment target, детальные пороги производительности
и правила восстановления полной истории. Это задачи проектирования и
проверки реализации; они не подменяются произвольными значениями в продуктовой
спецификации.

Перед реализацией каждого среза требуется проверить доступность нужных полей и
поведения GitHub и iOS. Перед выпуском — выполнить сценарии узла 0020,
проверки безопасности, доступности и работу на целевом устройстве. Сейчас эти
проверки ещё не проводились.
