Это изолированный pilot привязки к онтологии, не изменение рабочей
спецификации и не запись о действии оператора. Текущая selection GitView
остаётся на draft.5; новый action находится только в
[draft.6](../../candidates/domain-v0.2.0-draft.6/README.md).

## Что означает переход

Для ограниченного примера рассмотрим одно и то же `P` и `R1`:

```text
до:    P = {R1, R2}, Q = {R1}
вклад: User → RemoveRepository(R1) → P
после: P = {R2},     Q = {R1}
```

`projectIncludesRepository(P, R1)` описывает membership в наблюдаемом до-состоянии;
в после-состоянии именно этой принадлежности уже нет. Оно не становится вечным
фактом лишь из-за записи о более раннем действии. Предложение о действии и
переходе между состояниями не означает, что кто-то действительно выполнил его.
Чтение после-состояния без надёжного before и evidence самого действия не
доказывает ни акторство, ни то, когда и почему membership прекратилось.

Если `P` ранее уже не содержал `R1`, повторная попытка не доказывает новую
потерю membership. Если после удаления `R1` снова добавлен, старое действие
остаётся историческим, но текущее membership снова может существовать.
При отсутствующем или несовместимом наблюдении переход остаётся неизвестным.
Это семантические критерии для review; ни event admission, ни GitView storage,
ни механизм проверки текущей версии состояния ими не реализованы.

Пример обработчика в draft.6 выполняет конкретное изменение в памяти и
проверяет негативные случаи, но его поведение написано автором теста и не
следует автоматически из `ontologyc check`. Происхождение `RemoveRepository`
как отдельного доменного action и формальная модель lifecycle membership
остаются draft; не делаем нового свойства «удалён из» или сущности для UI.

## Вывод и дальнейший шаг

Временная терминологическая привязка к draft.6 технически разрешается. До
изменения рабочей selection нужно проверить, какие выбранные спецификации
действительно должны ссылаться на этот action, и отдельно проверить семантику
события, исходного/конечного состояния и их происхождение. Массовое добавление
имён ради `checked` не заменяет этот review.
