# Пилот типизированной ссылки на Repository

Один параметр `AddRepository.repository` указывает на экземпляр `Repository`.
В пилоте адресом служит ключ строки или тройка `graphKey / revisionKey / nodeId`.
Для обоих вариантов используется один обработчик действия.

Проверка использует исходники обоих вариантов пакета из `domain-v0.2.0-draft.3`
на GitView `0168449632f39afe672c59c4da91368ce0221518`. Скрипт сверяет SHA-256
исходника с закреплённой selection, меняет поле на временной копии и добавляет
суффикс `.refpilot` к версии пакета. Исходные selection и проектный контекст
не участвуют в продвижении этого эксперимента.

## Воспроизведение

Использованы компилятор и пример потребителя из коммита
`c79fc1dc9bfa8a673df2d1876fc2bc97fd4f0056` в [Ontology PR #99](https://github.com/0al-spec/Ontology/pull/99).
Из корня GitView, с Python 3
и PyYAML, Node и npm:

```sh
python3 ontology/pilots/typed-repository-reference/verify.py \
  --ontology-checkout /path/to/Ontology \
  --ontologyc /path/to/built/ontologyc
```

Зависимости TypeScript берутся из существующего lockfile проверки draft.3.
В основном и составном вариантах сгенерированный SDK прошёл strict typecheck
и выполнил один и тот же пример. Ключ и адрес узла привели к тому же экземпляру
`r2`; отсутствие строки, узла или ревизии сохранило членство исходного
репозитория. Подстановка `Ref<Project>` отклонена типом поля и схемой записи.
Индекс строк и граф находятся в памяти теста. Проверка подтверждает поведение
SDK и этого обработчика; проверка всей композиции супервизором сюда не входит.
