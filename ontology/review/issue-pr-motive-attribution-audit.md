# Issue, PullRequest и атрибуция мотива

Рабочий предмет GitView — GitHub Issue и Pull Request, при этом смысл этих
понятий не определяется экраном или Project. Issue фиксирует вопрос, проблему
или запрос; Pull Request оформляет предложение изменений для рассмотрения и
возможного включения. В GitView они показаны с контекстом исходного Repository.
Прямые ссылки на Issue или PullRequest присутствуют в 65 candidate specs;
данный разбор адресует их определения и контракты links/описаний, а не
заявляет семантическую проверку всех 65 узлов.

## Мотив и источник

Владелец предложил рассматривать Issue как мотив для актора: актор действует
над Code под этим мотивом, а PR выступает последствием. Это полезная
предметная интерпретация конкретного случая. Из самого наличия Issue, PR или
их source link нельзя вывести, что конкретный участник действовал именно под
этим мотивом и что PR действительно является следствием его действия.

В подключённом `motivcore@0.1.0` `Motive` — содержание побуждающей
причины, отделённое от scoped attribution. `MotivationHypothesis` связывает
предположение с одним мотивом и interpretation или interpretation candidate;
актор может остаться неизвестным, а отдельная поддержка не равна доказанной
истине. Этот пакет draft и описывает более общую интерпретацию, чем требуется
обычному обзору GitView. Он не устанавливает, что приложение должно создавать
hypotheses или хранить event model.

Экспериментальный `issueMotiveLink: Issue → motivcore:Motive` первоначально
создан для проверки композиции словаря. Это типизированная связь с отдельно
указанным motive content, а не выраженная акторная роль, действие, доказательство
или правило автоматического превращения Issue в Motive. Декларация не решает
тождество или различие экземпляров Issue и Motive и не доказывает, что эта
связь — окончательный способ моделировать предложенную владельцем идею.
Семантика, источник и уместность этой экспериментальной связи остаются
открытыми; существующий package не меняет определение общего Motive.

## Различия в проверяемых сценариях

| Основание | Что доступно | Чего недостаточно утверждать автоматически |
| --- | --- | --- |
| Source mention PR → Issue | Факт упоминания в его source scope | Мотив, действие, последствие и closing link |
| Source closing link | Отдельный тип связи при достаточном источнике | Что PR уже merged, Issue закрыта или вопрос решён |
| Авторский раздел Motivation со ссылкой на Issue | Текст автора и источник высказывания | Мотив каждого актора, истинность текста и фактическую причинность |
| Отдельное scoped attribution с поддержкой | Предложенное объяснение в пределах его основания | Верифицированную причинную историю без иных доказательств |

Отдельный актор может быть человеком, агентом или процессом; GitHub author
или reviewer не становится автоматически оператором GitView. PR — возможное
последствие в пользовательском примере, а не обязательный outcome всякого
действия и не доказательство достижения ожидаемого результата. Отсутствие
свидетельств мотива не доказывает отсутствие мотива.

Сценарий авторского текста и source link добавлен в 0034; источник и
интерпретация остаются раздельными. Политики импортированной онтологии и
примеры здесь не являются исполненным validation, GitHub запросами,
каноническим утверждением или доказательством действия реального актора.
