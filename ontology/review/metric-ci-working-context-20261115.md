# Metric и CIStatus в рабочем контексте GitView

Авторская содержательная сверка ограниченной области, не независимое review и
не semantic approval. Проверен исходный package
`local.gitview.domain@0.2.0-draft-composition.11` со статусом draft и SHA-256
`17b530b94f21ee78d6a8ee69a57f4ec1eafe4a02ff5973360cc811075fa22f7d`.
Исходные спецификации ниже остаются `idea / pre_canonical`; их ревизия —
содержимое commit `00f1cfb`, кроме случаев дальнейшего изменения файлов.

| Смысловая проверка | Package и потребители | Вывод и предел |
| --- | --- | --- |
| Отдельная check и агрегат | `CIStatus` — наблюдённое состояние одной source status-check entry; [0028](../../docs/drafts/GITVIEW-SPEC-0028.yaml) и [0041](../../docs/drafts/GITVIEW-SPEC-0041.yaml) отдельно описывают счётчики. | Согласовано по гранулярности: набор counters не становится одним CIStatus. Source mapping и применимость к revision по-прежнему требуют проверки. |
| Единица измерения | `Metric` — результат измерения с предметом, правилом и контекстом; [0057](../../docs/drafts/GITVIEW-SPEC-0057.yaml) различает failed checks и затронутые PR. | Пять checks на двух PR дают две разные величины. Нельзя считать их семь задачами или выводить mergeability. |
| График и измерение | [0068](../../docs/drafts/GITVIEW-SPEC-0068.yaml) предлагает точки наблюдений и отдельные outcome buckets; [0069](../../docs/drafts/GITVIEW-SPEC-0069.yaml) определяет временные и предметные границы. | Chart — представление результатов, а не новый Metric и не основание считать неизвестное значение нулём. Отдельная ontology entity для графика не нужна. |
| Историческое и текущее | 0057 различает динамический Today, прошлое состояние и события; 0069 различает event time и observation time. | Текущее число не доказывает прошлую точку; изменение числа не идентифицирует действие актора или событие на GitHub. |
| Review и CI | 0041 отделяет review assessment и количество тредов от checks. | Ни статус check, ни число открытых тредов сами по себе не определяют assessment, мотив или завершённость работы. |

`versionControlsCode` в том же package остаётся связью domain/range с прямо
указанным неопределённым действием. Из счётчиков PR и commit нельзя вывести,
кто выполнил действие над Code или какое свойство возникло: см. отдельный
[разбор VCS](version-control-action-boundary-20261114.md). Для текущих экранов
нет основания добавлять действие или менять package ради разрешения этого
вопроса. Аналогично не вводятся сущности Chart, Coverage или Refresh только
потому, что они используются в спецификациях.

Незакрыты формальная типизация контекста измерения, источник и полнота конкретных
checks, а также обоснование действия для VCS. Данная сверка не устанавливает
правильность каждого из 124 кандидатов, действительность source observations,
кардинальности конкретных объектов или применимость компилятора; она не
изменяет ontology package. Проверка draft.11 через `ontology-doctor` после
согласования настройки проекта дала `verified`, но compiler provenance и
семантическое принятие остались неустановленными.
