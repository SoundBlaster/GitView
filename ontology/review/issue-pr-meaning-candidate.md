# Issue и PullRequest: кандидаты значений и границы связей

Статус: **смысловой кандидат для review**, не утверждение целого package или
спецификаций. Исходный разбор подготовлен для draft.5; после
[дополнительной сверки](issue-pr-motive-attribution-audit.md) выбран рабочий
draft.9 с уточнёнными описаниями. Оба понятия остаются `ont:DomainEntity`,
package остаётся `draft`, а импорт `motivcore:Motive` не изменён.
Текущая рабочая композиция — [draft.13](../candidates/domain-v0.2.0-draft.13/README.md);
этот текст сохраняет историю первоначального рассмотрения, а не объявляет
draft.9 выбранной версией. Сверка текущих деклараций и границ находится в
[issue-pr-spec-alignment-20261115.md](issue-pr-spec-alignment-20261115.md).

## Понятия отдельно от свойств и связей

- **Issue** — зафиксированное в источнике обращение к вопросу, проблеме или
  запросу на работу. Это кандидатное значение: issue может содержать разные
  типы обсуждения и не доказывает, что работа началась или будет выполнена.
- **PullRequest** — оформленное в источнике предложение изменений для их
  рассмотрения и возможного включения. Его существование не означает, что
  изменения одобрены, влиты или достигли заявленного результата.

Это не определения через членство в Project или конкретное расположение в
интерфейсе. Repository context, название, source identity, номер, описание,
состояние и участники рассматриваются отдельно. Source-local номер сам по
себе не идентифицирует Issue или PR во всём портфеле. В текущем продукте
источник — GitHub; определения не утверждают применимость ко всем провайдерам.

## Связь, заявление и действие

| Доступное основание | Что оно выражает | Чего само по себе не доказывает |
| --- | --- | --- |
| PR упоминает Issue | Source link с указанным смыслом упоминания. | Что Issue является мотивом конкретного актора или что PR её закроет. |
| Source явно обозначает closing link | Source link другого типа, чем обычное упоминание. | Что merge уже произошёл, Issue закрыта или доказан мотив актора. |
| Автор написал Motivation в описании | Заявление автора с исходным текстом и контекстом. | Мотив всех участников, достоверность заявления или факт завершённого действия. |
| Актор действует над Code под мотивом Issue и следствием указан PR | Обсуждавшаяся владельцем возможная цепочка при наличии оснований для каждого звена. | Что всякая связанная Issue/PR пара имеет эту причинную историю. |

Участник в роли автора, assignee или reviewer не становится автоматически
оператором GitView или актором конкретного изменения. `User` — оператор,
как отдельно определено владельцем. Закрытие Issue и merge PR — различные
source facts; причина закрытия и доказательство достижения цели требуют
собственного основания. История закрытий и повторных открытий не выводится
из одного текущего состояния.

## Открытая граница с `Motive`

Владелец предложил рассматривать Issue как мотив действия актора. В draft.5
также есть кандидатный `issueMotiveLink: Issue → motivcore:Motive`. Само наличие
этой типизированной связи не доказывает тождество Issue и Motive, мотив
конкретного актора или действие, которое привело к PR. Как именно
пользовательская формулировка соотносится с импортированным понятием Motive и
какое свидетельство нужно для конкретного случая, остаётся открытым. Здесь не
создаётся новый `Motive`, actor/action relationship или автоматический вывод.

Предметные свойства и source links выбраны для GitView, но их полная
типизация, доступность и точный source mapping не установлены. Примеры здесь —
смысловая сверка, а не выполненные GitHub запросы или утверждённые определения.
