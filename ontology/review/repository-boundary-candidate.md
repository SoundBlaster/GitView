# Repository, Code и управление: смысловые границы

Статус: **кандидат для review**, не изменённый ontology package. Выбранный
`local.gitview.domain@0.2.0-draft-composition.5` остаётся `draft`.
Это исторический разбор draft.5; рабочий context обновлён до draft.11. Уточнение
VCS-действия для него находится в [отдельном разборе](version-control-action-boundary-20261114.md).

## Исходное различение

Владелец описал `Code` как по сути папку с файлами, а `Repository` — как Code,
в котором действует система контроля версий. Эта рабочая формулировка не
задаёт полную файловую модель, границы worktree или типы всех систем контроля
версий. `VersionControlSystem` обозначает систему; Git — обсуждавшийся пример.
Конкретное действие и состояние его выполнения не выводятся из одного имени.

`GitHubRepository` обозначает **тот же Repository** в контексте отношения
управления GitHub. В draft.5 это contextual protocol, а не отдельный класс
или второй Repository. `GitHub → RegisterRepository → Repository` — выбранная
модель действия и отношения управления в этом пакете; наблюдение объекта в API
само по себе не доказывает конкретное событие регистрации или его время.

## Identity, свойства и связи

| Наблюдение | Что следует в выбранном scope | Чего нельзя заключать |
| --- | --- | --- |
| Источник подтверждает тот же Repository после rename или transfer | Сохраняются identity, история и членство в Projects. | Что старый адрес продолжает указывать на тот же объект. |
| Адрес теперь принадлежит другому подтверждённому source ID | Это другой Repository; прежние memberships ему не переносятся. | Что совпадение названия или содержимого доказывает identity. |
| Repository принадлежит Projects P и Q | Две области использования одного Repository. | Что Projects тождественны или что их счётчики можно просто сложить. |
| Один Project исключил Repository | Меняется состав этого Project по product policy. | Удаление Repository у источника или прекращение управления GitHub. |
| Source возвращает 404 или неполное discovery | История и membership не удаляются только из-за ответа. | Подтверждённое удаление или explicit denial. |

Выбранная в 0002/0038 рабочая проверка использует numeric GitHub REST repository
ID в пределах одного GitHub instance. Это правило сопоставления наблюдений,
а не определение Repository через GitHub или универсальный ключ других систем.
Кодировка, другие схемы ID и межсерверное сопоставление остаются открытыми.

## Открытые вопросы

- `versionControlsCode` в draft.5 — link с domain/range; действие системы и
  возникающее свойство не определены. Нужно отдельно решить, требуется ли эта
  глубина для GitView и какие наблюдения её обоснуют.
- Отношение управления и период его действия отделены от факта наблюдения
  данных GitHub. Новые actions не выводятся автоматически из названия связи.
- Source address, membership, Code и Repository identity играют разные роли;
  локальный путь не становится универсальным ключом, а GitView не обязан
  загружать код только из-за наличия его понятия в онтологии.
